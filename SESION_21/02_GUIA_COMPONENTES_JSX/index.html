Tu primer componente de React: Navbar.jsx

SENA ADSO · Ficha 3229944 · Septiembre 2026

Sigue cada paso en orden. No avances al siguiente hasta que el anterior funcione y hayas marcado el check.
¿Qué construimos hoy?
Sacar el navbar de App.jsx y convertirlo en su propio componente

Hasta hoy, App.jsx contenía TODO el HTML de la página en un solo archivo. Hoy separamos el navbar en src/Navbar.jsx, lo exportamos, lo importamos de vuelta en App.jsx, y lo usamos como si fuera una etiqueta HTML: <Navbar />. El resultado visual no cambia — lo que cambia es la organización del código.

Paso 1
Crear src/Navbar.jsx con el navbar movido desde App.jsx
Paso 2
export default Navbar — decirle al archivo qué entrega
Paso 3
import Navbar + usar <Navbar /> dentro de App.jsx
Paso 1 · Componente

Crear src/Navbar.jsx

Un componente nuevo empieza como un archivo nuevo. Vamos a crear Navbar.jsx al lado de App.jsx, dentro de src/.

1

En VS Code, dentro de frontend-react/src/, crear un archivo nuevo llamado Navbar.jsx (mismo lugar donde está App.jsx).

El nombre del archivo empieza con mayúscula porque el componente que va adentro también empieza con mayúscula — es una convención, no una regla obligatoria de JavaScript, pero todo el ecosistema de React la sigue.
2

Mover el navbar de un archivo al otro — no se copia dejando el original, se traslada completo:

AcciónDónde
1. CortarEn App.jsx, seleccionar el bloque completo desde <nav> hasta </nav> y cortarlo (Ctrl+X) — queda vacío ese espacio en App.jsx
2. PegarEn Navbar.jsx, pegarlo (Ctrl+V) — ese es el bloque que se usará en el Paso 3 para armar la función

El bloque que se mueve es este — es el mismo navbar que viene funcionando desde S19/S20:

Bloque que se mueve de App.jsx a Navbar.jsxcortar y pegar
<nav className="flex items-center justify-between px-8 py-4 bg-white border-b border-slate-200">
  <div className="text-xl font-extrabold text-verde">
    TechStore Pro
  </div>
  <ul className="hidden md:flex gap-6 text-sm font-semibold text-texto-dim">
    <li>Inicio</li>
    <li>Productos</li>
    <li>Nosotros</li>
    <li>Contacto</li>
  </ul>
  <button className="bg-verde text-white py-2 px-5 rounded-lg font-bold text-sm">

Si tu navbar quedó distinto (por ejemplo sin el hidden md:flex del Paso 4 de S20), mueve el tuyo real — lo importante es trasladar exactamente lo que ya tienes, no reescribirlo.
No te preocupes por dejar App.jsx con errores momentáneamente — en el Paso 3 se termina de dejar funcionando otra vez, con <Navbar /> en el lugar donde estaba el navbar.
3

Envolver ese bloque pegado en Navbar.jsx dentro de una función llamada Navbar que lo devuelve con return — así queda convertido en componente:

frontend-react/src/Navbar.jsxcontenido completo
function Navbar() {
  return (
    <nav className="flex items-center justify-between px-8 py-4 bg-white border-b border-slate-200">
      <div className="text-xl font-extrabold text-verde">
        TechStore Pro
      </div>
      <ul className="hidden md:flex gap-6 text-sm font-semibold text-texto-dim">
        <li>Inicio</li>
        <li>Productos</li>
        <li>Nosotros</li>
        <li>Contacto</li>
      </ul>
      <button className="bg-verde text-white py-2 px-5 rounded-lg font-bold text-sm">
        Ingresar
      </button>
    </nav>
  )
}
ParteQué es
function Navbar()Declara el componente — nombre con mayúscula, sin parámetros por ahora
return (...)Lo que la función entrega cuando React la llama — en este caso, el JSX del navbar
( ) alrededor del JSXNo son obligatorios, pero permiten escribir el JSX en varias líneas sin errores de sintaxis
Cómo verificar: el archivo Navbar.jsx existe, tiene la función Navbar con el JSX del navbar adentro. Todavía no se usa en ningún lado — eso es normal, se conecta en el Paso 3.
Paso 2 · Conexión

Exportar el componente con export default

Por ahora, Navbar solo existe dentro de Navbar.jsx — ningún otro archivo puede verlo. export default es lo que lo hace disponible para ser importado desde otro archivo.

1

Al final de Navbar.jsx, después de la función, agregar una línea:

frontend-react/src/Navbar.jsxagregar al final
function Navbar() {
  return (
    <nav className="...">...</nav>
  )
}

export default Navbar
TrozoQué significa
exportMarca algo de este archivo como disponible para otros archivos
defaultIndica que es "lo principal que entrega este archivo" — por eso solo puede haber un export default por archivo
NavbarEl nombre de la función que se está exportando — debe coincidir exactamente con function Navbar()
Esto ya lo usaste desde S19 sin saberlo: la última línea de App.jsx siempre fue export default App. Es exactamente el mismo mecanismo — ahora lo aplicas en un archivo propio.
Cómo verificar: Navbar.jsx completo debe tener la función Navbar y, al final, export default Navbar — sin errores rojos de sintaxis en VS Code.
Paso 3 · Uso

Importar y usar <Navbar /> en App.jsx

Ahora en App.jsx: traer el componente con import, y usarlo en el espacio vacío que quedó como si fuera una etiqueta HTML.

1

Al principio de App.jsx, antes de function App(), agregar el import:

frontend-react/src/App.jsxagregar al inicio
import Navbar from './Navbar.jsx'

function App() {
  ...
TrozoQué significa
import NavbarTrae lo que ese archivo exportó por default — el nombre aquí lo elige quien importa
from './Navbar.jsx'Ruta al archivo — ./ significa "en esta misma carpeta"
2

Volver a App.jsx. En el espacio vacío que quedó dentro del return (...) — donde antes estaba el <nav>...</nav>, antes de cortarlo en el Paso 1 — escribir:

frontend-react/src/App.jsxescribir en el espacio vacío
<Navbar />

App.jsx completo debe quedar así:

frontend-react/src/App.jsxcómo queda
import Navbar from './Navbar.jsx'

function App() {
  return (

  <main className="max-w-6xl mx-auto px-6 py-10 flex flex-col gap-10">

    <Navbar />

    <section className="grid grid-cols-1 md:grid-cols-2 lg:grid-cols-3 gap-6">
      {/* Tarjeta 1, 2, 3 — sin cambios */}
    </section>

    <footer className="...">
      ...
    </footer>

  </main>
  )
}

export default App
ParteQué significa
<Navbar />Usa el componente como si fuera una etiqueta HTML propia — React lo reconoce por la mayúscula inicial
/ > al finalSe auto-cierra porque no tiene contenido adentro — igual que <img />
Cómo verificar: en localhost:5173, el navbar se debe ver exactamente igual que antes — mismo diseño, mismo texto, mismo comportamiento responsive (hidden md:flex). Nada cambia visualmente, solo la organización del código.
Paso 4 · Verificación

Confirmar que todo sigue funcionando

El objetivo de hoy no es cambiar el diseño — es reorganizar el código sin romper nada. Esta verificación confirma justamente eso.

1

Abrir localhost:5173 y revisar visualmente: el navbar (logo, links, botón Ingresar), el grid de 3 tarjetas de producto y el footer deben verse exactamente igual que en S20.

2

Abrir la consola del navegador (F12 → pestaña Console) y la terminal donde corre npm run dev. Ninguna de las dos debe mostrar errores rojos.

Si ves un error como Navbar is not defined, revisa que el import esté escrito exactamente igual al nombre de la función (Navbar, con mayúscula) y que la ruta './Navbar.jsx' sea correcta.
Antes de hoy
1 archivo (App.jsx) con navbar + catálogo + footer mezclados en el mismo return
Después de hoy
2 archivos: Navbar.jsx (componente propio) + App.jsx (usa <Navbar /> y ensambla el resto)
Cómo verificar: puedes probar temporalmente cambiar un texto dentro de Navbar.jsx (ej. "Ingresar" por "Entrar"), guardar, y ver que el cambio se refleja en localhost:5173 sin tocar App.jsx — eso confirma que el componente está realmente separado y conectado.
