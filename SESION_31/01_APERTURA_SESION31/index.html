Migrar el Carrito (parte 1): compras que se pueden revisar y editar

Hoy el carrito es solo un número en el Navbar: no se ve qué hay dentro, no se puede quitar un producto concreto y nadie sabe cuánto suma. En esta sesión nace la página del carrito: una lista con cantidades, un total que se calcula solo y un botón de pago que, por ahora, pide iniciar sesión. En el camino, tres ideas que se usan en toda aplicación de React: lo que se puede calcular no se guarda, el precio es texto y las listas se cambian creando una nueva.

Concepto · Estado derivado

Lo que se puede calcular, no se guarda

El carrito guarda una sola cosa: la lista de productos con su cantidad. El total, las unidades y el subtotal de cada fila salen de esa lista cada vez que la página se dibuja. Así nunca pueden contradecirla.

Estado — items (la lista del carrito)
↓ cada vez que React dibuja la página ↓
reduce — recorre la lista y suma
↓ devuelve un solo valor ↓
total
unidades
Cambias la lista y los dos números se recalculan solos: no hay nada más que actualizar.
Guardar el total en otro useState
Ahora hay dos datos que deben coincidir. Si una función cambia la lista y se olvida del total, la página muestra un precio falso.
→
Calcularlo al dibujar
Una sola fuente de verdad, la lista. El total es una operación sobre ella, no un dato aparte.

2 (suma, item) => suma + precioANumero(item.precio) * item.cantidad,

Práctica · precio.js

Para sumar, el precio tiene que ser un número

En la base de datos el precio es un texto con formato colombiano: "$8.999.000". Un texto no se puede multiplicar ni sumar. Se crea un archivo pequeño, precio.js, con dos funciones: una para ir de texto a número y otra para volver.

precio.js — el archivo nuevo
1export function precioANumero(precio) {
2 return Number(precio.replace(/[$.]/g, ""))
3}
4
5export function formatearPrecio(numero) {
6 return "$" + numero.toLocaleString("es-CO")
7}
Si haces esto…Obtienes…Por qué
"$8.999.000" + "$4.299.000""$8.999.000$4.299.000"Con textos, el + los pega en vez de sumarlos
Number("$8.999.000")NaNEl signo y los puntos no son parte de un número: Not a Number
parseFloat("8.999.000")8.999Se detiene en el segundo punto y devuelve casi nada: peor que un error, porque parece válido
Number("8999000")8999000Primero se quitan el $ y los puntos, y entonces sí
ParteQué hace
precio.replace(/[$.]/g, "")Quita todos los $ y todos los puntos. La g del final significa "todos", no solo el primero
Number(...)Convierte el texto limpio en un número de verdad, ya listo para multiplicar
numero.toLocaleString("es-CO")Escribe el número con puntos de miles al estilo de Colombia: 8999000 pasa a "8.999.000"
export functionUn archivo de utilidades no es un componente: exporta funciones con nombre y se importan con llaves, como claseInput en S30

Concepto · Listas inmutables

Para cambiar una lista, se crea una nueva

React decide si debe redibujar comparando la lista de antes con la de ahora. Si modificas la misma lista y se la devuelves, para React no cambió nada. Por eso nunca se usa push ni splice sobre el estado.

Tocar la lista original
items.push(producto) y luego setItems(items). Es la misma lista: React no ve diferencia y la pantalla no se actualiza.
→
Entregar una copia nueva
setItems([...items, producto]). Es otra lista: React la compara, ve que cambió y redibuja.
Quiero…Uso…Ejemplo en el carrito
Agregar uno[...items, nuevo]Un producto que todavía no estaba: se copia la lista y se pone el nuevo al final
Cambiar unoitems.map(...)Sumar una unidad: map recorre todos y devuelve una lista nueva donde solo cambia el que toca
Quitar unoitems.filter(...)Se queda con todos los que no son el que se quiere quitar
Identificar por id, no por posición
Quitar "el de la posición 1" cambia de significado cada vez que la lista se acorta. El id del producto no cambia nunca.
Guardar con un efecto
En vez de repetir localStorage.setItem en cada función, un useEffect con [items] guarda el carrito cada vez que cambia.

Práctica · CartContext

El mismo producto dos veces es una fila con cantidad 2

CartContext.jsx cambia por dentro. Los tres botones "Agregar" siguen llamando a agregarAlCarrito igual que antes: no hay que tocarlos.

12}

1item.id === producto.id ? { ...item, cantidad: item.cantidad + 1 } : item

Práctica · Controles de cada fila

Más, menos y quitar: tres botones por fila

Cada fila ofrece sumar una unidad, restar una y quitar el producto. Y muestra su subtotal: el precio por la cantidad, otra vez con puntos.

Carrito.jsx — los controles de una fila

5<span>{item.cantidad}</span>
6<button onClick={() => cambiarCantidad(item.id, 1)}>+</button>

1onClick={() => cambiarCantidad(item.id, -1)}

Los conceptos nuevos de hoy

Todo lo de S19 a S30 sigue funcionando igual. Esto es lo que se suma.

ConceptoQué significa
Estado derivadoLo que se puede calcular a partir del estado no se guarda aparte: se calcula al dibujar. Así nunca se contradice
reduceRecorre una lista y devuelve un solo valor, como el total o las unidades
Texto frente a número"$8.999.000" no se suma. Se quitan $ y puntos, se pasa a número, y se formatea al mostrar
Listas inmutablesNunca se toca la lista del estado: [...items, x], map y filter crean una lista nueva
Identificar por idLa posición en una lista cambia; el id no. Sirve para quitar, para cambiar y para la key
useEffect para guardarUn efecto con [items] guarda cada vez que la lista cambia, sin repetir el guardado en cada función
Estado del routernavegar(ruta, { state }) lleva un mensaje y un destino de regreso a la otra página
Confirmar con estadoUn booleano en useState cambia lo que se dibuja: una pregunta dentro de la página en vez de una ventana del navegador

Criterios de evaluación
  • Existe precio.js: convierte "$8.999.000" en 8999000 y devuelve "$8.999.000" con puntos
  • Agregar dos veces el mismo producto deja una fila con cantidad 2, y el Navbar cuenta unidades, no filas
  • La ruta /carrito muestra la lista con foto, nombre, precio, cantidad y subtotal; y, si está vacío, un mensaje con un enlace a los productos
  • "+" y "−" cambian la cantidad ("−" se desactiva en 1), "Quitar" elimina el producto, y el total siempre coincide con la suma
  • "Vaciar carrito" pregunta antes, dentro de la página, y no usa ventanas del navegador
  • Sin sesión, "Inicia sesión para pagar" lleva a /login con un aviso y, al entrar, vuelve al carrito
  • Recargar con F5 conserva el carrito, y "Salir" de la sesión no lo vacía
  • Sin errores en consola ni en las terminales, y sin scroll horizontal a 390px de ancho
