Paso 1 · Preparación

Un punto de retorno antes de mover archivos

Hasta hoy todos los archivos viven sueltos dentro de src: ya son 21 y buscar uno es incómodo. Hoy los ordenamos en carpetas. No cambia nada de lo que hace la tienda: solo cambia dónde vive cada archivo y, por eso, las líneas import que los conectan. Mover archivos y arreglar rutas es un trabajo delicado, así que primero guardamos un punto de retorno.

1

Comprueba que todo funciona antes de empezar. Con el frontend encendido (npm run dev dentro de frontend-react/), recorre la tienda: Inicio, Productos, un detalle, Carrito, Login.

Cómo verificar: todas las páginas abren sin pantalla en blanco y la terminal del frontend no muestra errores en rojo. Si algo ya falla ahora, no sigas: arréglalo primero, o no sabrás si el fallo es de antes o del movimiento.
2

Guarda el estado actual en Git. Abre una terminal en la carpeta del proyecto (la que contiene backend y frontend-react) y ejecuta:

terminal — carpeta del proyecto
git add .
git commit -m "S31: antes de ordenar en carpetas"
Este commit es tu botón de deshacer. Si en algún momento todo se desordena y no sabes volver, escribe git reset --hard HEAD y el proyecto regresa exacto a este punto. No hace falta git push todavía: se sube al final.
Paso 2 · Las carpetas

Crear tres carpetas y mover los archivos

Tres carpetas, tres tipos de archivo: components guarda las piezas pequeñas que se reutilizan, pages guarda las páginas completas (cada una tiene su ruta) y context guarda el estado compartido. Todo el movimiento se hace con comandos, así es rápido y no hay que arrastrar archivo por archivo.

1

Esta tabla dice a dónde va cada archivo. Léela antes de ejecutar los comandos:

CarpetaArchivos que van dentro
contextAuthContext.jsx, CartContext.jsx
componentsNavbar.jsx, Footer.jsx, ProductCard.jsx, ProductoModal.jsx, Campo.jsx, Contador.jsx, BadgeCarrito.jsx
pagesHome.jsx, Productos.jsx, ProductoDetalle.jsx, Nosotros.jsx, Contacto.jsx, Login.jsx, Registro.jsx, Carrito.jsx, NotFound.jsx
src (se quedan)App.jsx, main.jsx, App.css, index.css, assets/ y utils/
2

Abre una terminal en la carpeta del proyecto (la que contiene backend y frontend-react) y entra a src. Mac, o Git Bash en Windows:

terminal — Mac o Git Bash
cd frontend-react/src
mkdir components pages context

Windows con PowerShell (la única diferencia es cómo se escribe mkdir con varios nombres: con comas):

Cómo verificar: en el panel lateral de VS Code, dentro de src, aparecen las carpetas components, pages y context (vacías por ahora).
3

Ahora los tres comandos que mueven los archivos. Son iguales en Mac y en Windows. Cópialos y pégalos uno por uno, dentro de frontend-react/src:

terminal — dentro de frontend-react/src
git mv AuthContext.jsx CartContext.jsx context
git mv Navbar.jsx Footer.jsx ProductCard.jsx ProductoModal.jsx Campo.jsx Contador.jsx BadgeCarrito.jsx components
git mv Home.jsx Productos.jsx ProductoDetalle.jsx Nosotros.jsx Contacto.jsx Login.jsx Registro.jsx Carrito.jsx NotFound.jsx pages
ParteQué hace
git mvMueve un archivo y le avisa a Git. Es lo mismo que arrastrarlo, pero Git entiende que es el mismo archivo en otro lugar y no que borraste uno y creaste otro
AuthContext.jsx CartContext.jsxLos archivos a mover: se pueden poner varios, separados por espacios
contextLo último de cada comando es la carpeta de destino
El comando git mv solo mueve archivos que Git ya conoce. Por eso el Paso 1 pedía hacer el commit antes: si saltaste ese paso, te dirá not under version control. Vuelve al Paso 1.
Cómo verificar: escribe ls (en Mac o Git Bash) o dir (en PowerShell) dentro de src: solo quedan App.jsx, main.jsx, los dos .css, assets, utils y las tres carpetas nuevas. Ningún componente suelto.
4

Mira la terminal del frontend y el navegador: ahora la tienda está rota a propósito. Verás mensajes en rojo como este:

terminal del frontend (ejemplo)

Es normal: cada archivo sigue buscando a sus vecinos donde estaban antes. El mensaje te dice en qué archivo (from "src/components/Navbar.jsx") está la ruta equivocada. Ese mensaje será tu guía en los pasos 3, 4 y 5: cuando termine de quejarse, está listo.
Paso 3 · Cómo se escribe una ruta

Arreglar main.jsx y App.jsx

Un import lleva una ruta: dónde está el archivo, contado desde el archivo que lo importa. Se lee así:

1
RutaSignificaEjemplo
./Esta misma carpetaDesde App.jsx (en src): ./components/Navbar.jsx entra a components
../Subir una carpetaDesde components/Navbar.jsx: ../context/CartContext.jsx sube a src y entra a context
Regla práctica: pregunta desde dónde estoy yo. Si estoy dentro de components o pages y quiero llegar a otra carpeta, primero subo con ../. Si estoy en src (como App.jsx y main.jsx), no subo: entro directo con ./.
2

Abre frontend-react/src/main.jsx. Solo cambian dos líneas, las de los contextos (las amarillas). Las demás se quedan igual, y todo lo que está debajo de los imports no se toca:

Paso 6 · Lo que quedó fuera

Qué archivos no se movieron y por qué

Ordenar no es solo mover: también hay que saber qué se queda donde estaba y qué archivos sobran. Vas a revisar el proyecto con la herramienta de búsqueda de VS Code, sin cambiar nada todavía.

1

Estos archivos no se movieron y cada uno tiene su razón:

ArchivoPor qué se queda donde está
src/main.jsxEs la puerta de entrada: el index.html (que está fuera de src) lo llama con /src/main.jsx. Si lo movieras, habría que cambiar también ese archivo
src/App.jsxEs la raíz de la aplicación y reúne las rutas. Vive junto a main.jsx
src/index.cssLo importa main.jsx y trae Tailwind y los estilos globales
src/utils/Ya es una carpeta: la creaste en el Paso 2 de la guía anterior
public/favicon.svgEl ícono de la pestaña. La carpeta public está fuera de src y Vite la sirve tal cual; index.html lo llama como /favicon.svg
2

Ahora busca lo que nadie usa. En VS Code pulsa Ctrl + Shift + F (en Mac, Cmd + Shift + F), escribe cada nombre de la tabla y mira cuántos resultados salen:

Escribe en la búsquedaQué verásQué significa
hero.pngSin resultadosLa imagen src/assets/hero.png no se usa en ningún archivo
react.svg y vite.svgSin resultadosLos dos íconos de src/assets/ son del proyecto de ejemplo que crea Vite y no se usan
App.cssSin resultadosNingún archivo importa src/App.css: es otra sobra del ejemplo de Vite
icons.svgSin resultadosTampoco se usa public/icons.svg
ContadorSolo aparece su propio archivoNadie importa components/Contador.jsx: lo hicimos en S23 para practicar useState
BadgeCarritoSolo aparece su propio archivoNadie importa components/BadgeCarrito.jsx: el contador del carrito ahora vive en el Navbar
Buscar el nombre de un archivo en todo el proyecto es la forma segura de saber si se usa. Si no aparece en ningún import ni en ningún src=, nadie lo necesita. Haz esto siempre antes de borrar o mover algo.
Cómo verificar: coinciden los seis resultados de la tabla. Si alguno aparece en un import de tu proyecto, ese archivo sí se usa: no lo borres.
3

Reto opcional — limpiar lo que sobra. Hoy no se borra nada obligatorio, porque un archivo sin usar no rompe la tienda. Si quieres dejar el proyecto limpio, elimina lo que la búsqueda confirmó que nadie usa: la carpeta src/assets/, el archivo src/App.css y public/icons.svg. En la terminal, dentro de la carpeta del proyecto:

terminal — carpeta del proyecto (la que contiene backend y frontend-react)
git rm -r frontend-react/src/assets
git rm frontend-react/src/App.css frontend-react/public/icons.svg
Deja Contador.jsx y BadgeCarrito.jsx en su lugar: son ejemplos de sesiones anteriores y se pueden consultar. Después de borrar, recorre la tienda (Paso 7) para confirmar que todo sigue igual; con git reset --hard HEAD recuperas lo que borraste si no hiciste el commit del Paso 8.

Paso 8 · Git

Guardar tu avance y compartirlo con el instructor

Una sesión no termina cuando funciona en tu computador, sino cuando queda guardada y compartida. Haces un commit (una foto de tu proyecto en este momento), lo subes a GitHub y, si todavía no lo hiciste, le das acceso al instructor (Jtrujillosena).

1

Abre una terminal en la carpeta que contiene backend y frontend-react y mira si ya está conectada a un repositorio de GitHub:

terminal — en la carpeta del proyecto
git remote -v
Qué vesQué significaQué haces
Dos líneas con origin y una dirección https://github.com/...Ya está conectada a tu repositorioSigue al punto 2
No sale nadaTodavía no está conectada a GitHubHaz lo de abajo y después sigue al punto 2

git branch -M main
Cómo verificar: git remote -v muestra tu dirección de GitHub en dos líneas.
2

Antes de subir nada, revisa qué vas a subir. Hay archivos que jamás deben llegar a GitHub, como el .env (tiene las claves de tu base de datos) y la carpeta node_modules:

terminal — en la carpeta del proyecto
git status
Cómo verificar: en la lista aparecen tus archivos de código (el avance de hoy) y no aparece ningún .env ni node_modules.
Si ves .env o node_modules en la lista, no sigas. Significa que falta el archivo .gitignore o que está mal escrito. Avisa al instructor antes de hacer git add: una clave subida a GitHub hay que cambiarla, aunque la borres después.
