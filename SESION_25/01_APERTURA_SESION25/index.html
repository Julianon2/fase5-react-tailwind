SLIDE 04 / 14
El problema

TechStore Pro no tiene páginas — todavía

Desde S19, todo (navbar, buscador, catálogo, footer) vive dentro de App.jsx. Los links del navbar (Inicio, Productos, Nosotros, Contacto) son solo texto — no llevan a ningún lado.

Los links del navbar no hacen nada
Son <li> sin href ni destino — visualmente parecen navegación, pero no navegan.
Un solo archivo, todo el sitio
Home, Productos, Nosotros y Contacto deberían ser 4 pantallas distintas — hoy solo existe una.
Esto no es un error, es una etapa
En S19-S24 el foco era aprender componentes, props, estado y conexión a datos reales — todo eso funcionaba igual de bien en una sola pantalla. Hoy, con esas bases ya sólidas, toca resolver la navegación real entre páginas.

Concepto

react-router-dom — URLs sin recargar la página

Es una librería (no viene incluida en React) que conecta la URL del navegador con qué componente se muestra — sin que el navegador recargue nada.

localhost:5173/
Página Home
Contenido de la portada
Prueba los botones — la URL cambia, el contenido cambia, pero la página NUNCA parpadea ni recarga.
main.jsx — envolver la app
1import { BrowserRouter } from 'react-router-dom'
2
3<BrowserRouter>
4 <App />
5</BrowserRouter>
// en palabras normales
BrowserRouter = el componente que habilita la navegación
↓
"Envuelve toda la app para que pueda leer y cambiar la URL sin recargar — sin esto, <Link> y las rutas no funcionan."
SLIDE 06 / 14
Concepto

Routes y Route — el mapa de páginas

Dentro de App.jsx, <Routes> es la lista de todas las URLs posibles, y cada <Route> dice qué componente mostrar en cada una.

App.jsx — el mapa de rutas
1import { Routes, Route } from 'react-router-dom'
2
3<Routes>
4 <Route path="/" element={<Home />} />
5 <Route path="/productos" element={<Productos />} />
6</Routes>
ParteQué es
<Routes>Contenedor — agrupa todas las rutas posibles de la app
<Route path="/" ...>La URL exacta a la que responde esta ruta — "/" es la raíz del sitio
element={<Home />}Qué componente se dibuja cuando la URL coincide con ese path
Solo una Route coincide a la vez
React Router busca de arriba hacia abajo y muestra la primera <Route> cuyo path coincida con la URL actual — nunca dos páginas a la vez.
SLIDE 07 / 14
Concepto

<Link> vs <a> — la diferencia que importa

Ambos se ven igual en pantalla y ambos cambian la URL — pero por dentro hacen algo completamente distinto.

<a href="/productos">
Le dice al navegador "descarga esta página desde cero" — recarga TODO: HTML, CSS, JS, y pierde cualquier estado de React (como lo que había en el buscador).
VS
<Link to="/productos">
Intercepta el clic, cambia la URL con JavaScript, y le pide a React Router que dibuje el componente nuevo — sin tocar el navegador.
Navbar.jsx — reemplazar li por Link
1// antes
2<li>Productos</li>
3
4// después
5<Link to="/productos">Productos</Link>
Regla simple
Dentro de una app de React con React Router, usa <Link> para navegar entre páginas internas del sitio. <a> normal se reserva para enlaces externos (otro sitio web, no parte de TechStore Pro).
SLIDE 08 / 14
Concepto

Parámetros de ruta — una URL que cambia

No todas las rutas son fijas. :id en una ruta significa "aquí va un valor variable" — necesario para la página de detalle de cada producto (S29).

Una ruta con parámetro
1<Route path="/producto/:id" element={<ProductoDetalle />} />
URL real¿Coincide con /producto/:id?
/producto/64a1f2Sí — :id = "64a1f2"
/producto/7Sí — :id = "7"
/productoNo — falta la parte después de /producto/
Esto no se usa todavía, pero ya se entiende
Hoy solo se definen rutas fijas (/ y /productos). Los parámetros de ruta (:id) se usan en la Sesión 29, cuando cada producto tenga su propia página de detalle — por eso se explican hoy, para que no sea nuevo cuando llegue ese momento.
