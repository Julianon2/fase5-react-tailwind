Concepto · Componente nuevo

ProductoModal: el modal es un componente más

Un modal no es magia: es un componente que se dibuja encima del resto. Recibe el producto a mostrar y una función para avisar que quiere cerrarse, igual que ProductCard recibe sus datos por props (S22).

ProductoModal.jsx — la firma del componente
1function ProductoModal({ producto, onCerrar }) {
2 return (
3 <div className="fixed inset-0 z-50 ...">
4 <h2>{producto.nombre}</h2>
5 <p>{producto.descripcion}</p>
6 </div>
7 )
8}
producto: los datos
Un objeto completo (id, nombre, precio, imagen, descripcion). El modal solo lo lee y lo dibuja.
onCerrar: un aviso hacia arriba
Una función que el padre le presta. El modal no sabe qué hace: solo la llama cuando el usuario quiere cerrar.
fixed inset-0 z-50
Una capa que cubre toda la pantalla y se coloca por encima de todo lo demás, sin importar dónde se escribió en el código.
Productos.jsx — dónde se usa
1seleccionado && (
2 <ProductoModal
3 producto={seleccionado}
4 onCerrar={() => setSeleccionado(null)}
5 />
6)
Renderizado condicional
Si seleccionado es null, no se dibuja nada. Si tiene un producto, aparece el modal. Es el mismo && del buscador.
Cerrar = volver a null
setSeleccionado(null) hace que la condición sea falsa y el modal desaparece solo.
SLIDE 06 / 14
Concepto · Levantar el estado

¿Quién guarda "qué producto está abierto"?

La tarjeta es la que recibe el clic. El modal es el que muestra el producto. Son dos componentes hermanos que necesitan saber lo mismo. La solución: ese dato vive en el padre común, Productos.

Productos — guarda "seleccionado"
↓ onVer / producto ↓
ProductCard — avisa con onVer
ProductoModal — lee producto
La tarjeta avisa hacia arriba, el padre cambia el estado y el modal lo recibe hacia abajo.
Datos: del padre al hijo
Por props. El padre le entrega al modal el producto que debe dibujar.
Avisos: del hijo al padre
También por props, pero como funciones. La tarjeta recibe onVer y la llama cuando alguien hace clic.
Levantar el estado
Nombre del patrón: cuando dos hermanos necesitan el mismo dato, el estado se sube al padre que los contiene a ambos.

Práctica · Abrir el modal

Del clic en la tarjeta al modal abierto

Tres líneas hacen todo el recorrido: un estado en el padre, una función prestada a la tarjeta y un clic que la llama.

Productos.jsx — el estado y el aviso
1const [seleccionado, setSeleccionado] = useState(null)
2
3<ProductCard
4 key={p.id}
5 nombre={p.nombre}
6 onVer=() => setSeleccionado(p)
7/>
ProductCard.jsx — dónde se escucha el clic
1<article
2 onClick={props.onVer}
3 className="... cursor-pointer"
4>
// las 3 piezas del aviso, en palabras normales
onVer = el nombre del aviso  ·  () => = una función que se ejecuta al hacer clic  ·  p = el producto de esta tarjeta
↓ ↓ ↓
"La tarjeta llama a onVer cuando la tocan; esa función guarda este producto como el seleccionado en Productos."
ParteQué hace
useState(null)Empieza en null: ningún producto abierto. Al hacer clic pasa a ser el objeto completo del producto.
onVer={() => setSeleccionado(p)}Una función nueva por cada tarjeta, que recuerda cuál es su p. Se le presta a la tarjeta como si fuera cualquier otra prop.
onClick={props.onVer}La tarjeta conecta el clic con la función que le prestaron, sin saber qué hace por dentro.
cursor-pointerCambia el cursor a una manita: avisa que la tarjeta se puede pulsar.

Concepto · Burbujeo de eventos

Un clic que llega a donde no debería

Los eventos "burbujean": un clic en un elemento también cuenta como clic para todos los que lo contienen. Dentro de la tarjeta está el botón Agregar +, y al pulsarlo se abriría también el modal.

Sin frenar el clic
Pulsas "Agregar +": el producto entra al carrito, y el clic sube a la tarjeta, que también abre el modal. Dos cosas a la vez, y solo querías una.
→
Con stopPropagation
El botón corta el recorrido del clic hacia arriba. Solo se agrega al carrito, y la tarjeta ni se entera.
ProductCard.jsx — frenar el clic en el botón
1function agregar(e) {
2 e.stopPropagation()
3 agregarAlCarrito({ ... })
4}
// las 2 piezas, en palabras normales
e = el evento del clic  ·  e.stopPropagation() = detener el recorrido hacia arriba
↓ ↓
"Recibe el evento y le pide que no siga subiendo hacia la tarjeta."
El mismo truco, al revés, en el modal
El fondo oscuro del modal cierra al hacer clic. Pero el panel blanco está dentro del fondo: un clic en la ficha subiría al fondo y la cerraría. Por eso el panel lleva onClick={(e) => e.stopPropagation()}.

Concepto · Limpieza de useEffect

Cerrar con Escape y bloquear el scroll

Esto es trabajo con el navegador, fuera de React: por eso va en useEffect (S24). Lo nuevo es que lo que se enciende al abrir el modal hay que apagarlo al cerrarlo.

ProductoModal.jsx — useEffect con limpieza
1useEffect(() => {
2 function alPulsar(e) {
3 if (e.key === "Escape") onCerrar()
4 }
5 document.addEventListener("keydown", alPulsar)
6 document.body.style.overflow = "hidden"
7
8 return () => {
9 document.removeEventListener("keydown", alPulsar)
10 document.body.style.overflow = ""
11 }
12}, [onCerrar])
Lo que se enciende
Al abrirse el modal: se empieza a escuchar el teclado y se bloquea el scroll de la página de atrás.
Lo que se apaga: el return
La función que devuelve el efecto es la limpieza: React la ejecuta cuando el modal desaparece. Deshace todo lo del paso anterior.
Sin limpieza
La página quedaría sin scroll para siempre, y cada vez que abras el modal se sumaría otro oyente de teclado.
ParteQué hace
e.key === "Escape"e.key dice qué tecla se pulsó. Solo se actúa con Escape.
document.body.style.overflowCon "hidden" el cuerpo de la página no se desplaza; con "" vuelve a su comportamiento normal.
[onCerrar]La lista de dependencias: el efecto se vuelve a armar si cambia onCerrar, para no usar una versión vieja de esa función.

Concepto · Ordenar datos

El precio llega como texto

El backend guarda "$8.999.000", no el número 8999000. Para comparar precios hay que convertirlo, y para ordenar sin dañar la lista original, hay que trabajar con una copia.

Productos.jsx — del texto al número
1function precioNumero(p) {
2 return Number(p.precio.replace(/\D/g, ""))
3}
// las 3 piezas, en palabras normales
p.precio = "$8.999.000"  ·  .replace(/\D/g, "") = quitar todo lo que no sea dígito  ·  Number(...) = convertir el texto en número
↓ ↓ ↓
"Del texto $8.999.000, se queda solo con los dígitos y lo convierte en el número 8999000."
Productos.jsx — ordenar sin dañar la original
1const ordenados = [...filtrados]
2 .sort((a, b) => precioNumero(a) - precioNumero(b))
// las 2 piezas, en palabras normales
[...filtrados] = una copia de la lista  ·  .sort(...) = ordena de menor a mayor
↓ ↓
"Hace una copia y la ordena restando precios; la lista original queda intacta."
.sort() modifica el arreglo
Si se ordena filtrados directamente, se cambia la lista que otros usan. Por eso primero se copia con [...filtrados].
Un select controlado
El orden elegido vive en un estado (orden), igual que el buscador. Tres opciones: original, menor precio y mayor precio.
Mayor a menor: se invierte la resta
precioNumero(b) - precioNumero(a). Cambiar el orden de la resta cambia la dirección.
