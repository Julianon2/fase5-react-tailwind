Ejercicio 1

Avisar que el producto ya se agregó

Hoy, al pulsar "Agregar al carrito" en la ficha solo sube el contador del Navbar, y el botón queda igual: nada confirma que funcionó, y se puede pulsar diez veces seguidas. Aquí el botón cambia de texto y se deshabilita con un estado (S23). Tiempo estimado: 10 minutos. Archivo: src/ProductoDetalle.jsx.

1

Con los dos servidores arriba, abre la ficha de cualquier producto y pulsa "Agregar al carrito" varias veces. El contador sube cada vez y el botón no avisa nada. Ese es el síntoma que vas a corregir.

2

Abre src/ProductoDetalle.jsx. Primero el estado. Este paso ya viene resuelto como modelo: va debajo de los otros useState.

3

4

Último paso, escrito por ti: conecta el estado al botón. disabled debe valer lo mismo que agregado, y el texto del botón cambia con un operador ternario (condición ? si_verdadero : si_falso, S24):

PiezaQué hace

Guardar tu avance y compartirlo con el instructor

Una sesión no termina cuando funciona en tu computador, sino cuando queda guardada y compartida. Haces un commit (una foto de tu proyecto en este momento), lo subes a GitHub y, si todavía no lo hiciste, le das acceso al instructor (Jtrujillosena).

1

Abre una terminal en la carpeta que contiene backend y frontend-react y mira si ya está conectada a un repositorio de GitHub:

terminal — en la carpeta del proyecto
git remote -v
Qué vesQué significaQué haces
Dos líneas con origin y una dirección https://github.com/...Ya está conectada a tu repositorioSigue al punto 2
No sale nadaTodavía no está conectada a GitHubHaz lo de abajo y después sigue al punto 2

Solo si no salió nada: ejecuta, una línea a la vez (cambia la dirección por la de tu repositorio):

terminal — solo la primera vez
git init
git remote add origin https://github.com/TU-USUARIO/techstore-fase5.git
git branch -M main
Cómo verificar: git remote -v muestra tu dirección de GitHub en dos líneas.
2

Antes de subir nada, revisa qué vas a subir. Hay archivos que jamás deben llegar a GitHub, como el .env (tiene las claves de tu base de datos) y la carpeta node_modules:

terminal — en la carpeta del proyecto
git status
Cómo verificar: en la lista aparecen tus archivos de código (tus ejercicios de hoy) y no aparece ningún .env ni node_modules.
Si ves .env o node_modules en la lista, no sigas. Significa que falta el archivo .gitignore o que está mal escrito. Avisa al instructor antes de hacer git add: una clave subida a GitHub hay que cambiarla, aunque la borres después.
3

Guarda tus ejercicios de hoy y súbelo. Los tres comandos, una línea a la vez:

terminal — en la carpeta del proyecto
git add .
git commit -m "S29: ejercicios de detalle de producto"
git push
ComandoQué hace
git add .Marca todos los cambios para la foto (el punto significa "todo lo de esta carpeta")
git commit -m "..."Toma la foto y le pone un mensaje que dice qué hiciste hoy. Escríbelo corto y claro
git pushSube la foto a GitHub. La primera vez en un repositorio nuevo, si Git dice que no hay rama de destino, usa git push -u origin main
Cómo verificar: git status dice nothing to commit, working tree clean. Y al abrir tu repositorio en GitHub aparece tu commit de hoy arriba, con el mensaje que escribiste.
4

Comparte el proyecto con el instructor. Si ya lo hiciste en la S19, solo comprueba que Jtrujillosena sigue en la lista de Collaborators. Si no, hazlo ahora. Su cuenta de GitHub es Jtrujillosena (https://github.com/Jtrujillosena). En tu repositorio de GitHub:
