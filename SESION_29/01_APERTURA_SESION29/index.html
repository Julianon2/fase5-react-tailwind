Migrar Producto: una página para cada producto

El modal de la sesión pasada es una vista rápida. Hoy cada producto gana su propia página, con una dirección que se puede copiar, compartir y recargar sin perder nada. SLIDE 05 / 15
Concepto · Rutas dinámicas

Una página, muchos productos

Hasta hoy cada ruta era una dirección fija: /productos, /contacto. Una tienda no puede crear una ruta por producto. Se escribe una sola, con un hueco que cambia.

App.jsx — la ruta con parámetro
1<Routes>
2 <Route path="/productos" element={<Productos />} />
3 <Route path="/productos/:id" element={<ProductoDetalle />} />
4 <Route path="*" element={<NotFound />} />
5</Routes>
ProductoDetalle.jsx — leer el parámetro
1const { id } = useParams()
// las 2 piezas, en palabras normales
useParams() = pedirle al router los parámetros de la dirección  ·  id = el valor que estaba en el hueco :id
↓ ↓
"Pregúntale al router qué hay en la dirección y quédate con el id."
El dos puntos marca el hueco
En /productos/:id el :id no es texto fijo: es un nombre para lo que venga en esa posición de la dirección.
El nombre debe coincidir
Lo que escribes después de : es lo que desestructuras de useParams(). Si la ruta dice :id, buscas id.
Siempre llega como texto
Aunque la dirección diga /productos/5, id vale "5", una cadena. Hoy no se convierte porque el backend lo recibe igual.
SLIDE 06 / 15
Concepto · Flujo de datos

La dirección manda

En el catálogo el dato venía del estado. Aquí viene de la dirección: la URL es la fuente. Por eso recargar o pegar el enlace funciona, y el modal no.

La dirección — /productos/66a1…
↓ useParams ↓
ProductoDetalle — lee el id
↓ fetch ↓
Backend — GET /api/productos/:id
Estado — guarda el producto
La dirección cambia el id, el id dispara el fetch, y la respuesta llena el estado que dibuja la ficha.
Recargar funciona
Al recargar, React arranca de cero, pero la dirección sigue ahí: se lee el id otra vez y se vuelve a pedir el producto.
El enlace se comparte
Quien reciba la dirección ve el mismo producto, sin haber pasado por el catálogo.
El modal no sobrevive
Su estado vive en memoria: al recargar, seleccionado vuelve a ser null y el modal desaparece.

Concepto · Estados de una página

Una página que carga datos tiene cuatro caras

El mismo componente se dibuja distinto según en qué momento está. Decidirlo con if y return temprano mantiene el código ordenado.

ProductoDetalle.jsx — antes de dibujar la ficha
1if (cargando) return <p>Cargando producto...</p>
2
3if (error) return (
4 <div>
5 <p>{error}</p>
6 <Link to="/productos">Volver al catálogo</Link>
7 </div>
8)
9
10// aquí ya hay un producto: se dibuja la ficha completa
Cargando
Mientras llega la respuesta. Evita dibujar la ficha con datos que todavía no existen.
Error o no encontrado
Un id que no existe o una dirección escrita a mano. El backend responde 404 y la página lo explica con un enlace de salida.
Listo
Hay un producto en el estado: se dibujan foto, nombre, descripción, precio y botón.
Return temprano
Si cargando es verdadero, la función termina ahí con return y el resto no se ejecuta. Así el código de la ficha no necesita preguntar a cada paso si producto existe.
SLIDE 09 / 15
Concepto · id y _id

La dirección usa el _id de Mongo, no el id del catálogo

Cada producto tiene dos identificadores. Confundirlos es el error más común de esta sesión: el backend busca con findById, que usa el _id.

id — el número del catálogo
1, 2, 3… es el que muestra "REF 01" en la tarjeta y el que usa el carrito. Sirve para mostrar, no para buscar en Mongo.
≠
_id — el identificador de Mongo
Una cadena larga que Mongo crea sola, como 66a1f0…. Es la que va en la dirección y la que entiende findById.
ProductoModal.jsx — el enlace usa _id
1<Link to={"/productos/" + producto._id}>
2 Ver ficha completa
3</Link>
Si pones el id numérico
La dirección /productos/3 llega al backend como findById("3"), que no es un _id válido: responde 404 y la página muestra "Producto no encontrado". El mensaje de error es correcto; el enlace es el que está mal.

Práctica · Link

Del modal a la página

El modal sigue siendo la vista rápida. Gana un enlace para quien quiera ver el producto completo. Se usa Link (S25), no una etiqueta a.

ProductoModal.jsx — el enlace
1<Link
2 to={"/productos/" + producto._id}
3 className="..."
4>
5 Ver ficha completa
6</Link>
// las 3 piezas, en palabras normales
Link = navegar sin recargar la página  ·  to = la dirección de destino  ·  "/productos/" + producto._id = se arma con el _id de este producto
↓ ↓ ↓
"Viaja a la dirección del producto que está abierto, sin recargar la página."
Una etiqueta a recarga todo
Con href el navegador pide la página completa al servidor y React arranca de cero. Con Link solo cambia la parte de la pantalla que corresponde.
Y la limpieza del modal
Al navegar, el modal desaparece de pantalla. La limpieza de useEffect (S28) se ejecuta y devuelve el scroll a la página. Sin ella la ficha quedaría sin desplazamiento.

Concepto · Pulido

Tres detalles que se notan

Con lo anterior la página funciona. Estos tres detalles hacen que se sienta de tienda.

El título de la pestaña
La pestaña del navegador dice "TechStore" en todas partes. Con document.title dentro de un efecto muestra el nombre del producto, y la limpieza (S28) lo deja como estaba al salir.
Una salida clara
Un Link "Volver al catálogo" arriba de la ficha. Sin él, el único camino de regreso es el botón del navegador.
El menú sigue en Productos
El Navbar usa NavLink (S25): /productos/66a… sigue contando como una página de Productos, y la opción continúa marcada.
ProductoDetalle.jsx — agregar al carrito
1const { agregarAlCarrito } = useContext(CartContext)
2

Lo mismo que ya sabes
El carrito guarda el id numérico, no el _id. La ficha usa los mismos campos que la tarjeta y el modal, así los tres botones agregan exactamente lo mismo.

Cierre · Sesión 29

¡Empezamos!

Criterios de evaluación
  • App.jsx tiene la ruta /productos/:id antes de la ruta comodín, y ProductoDetalle.jsx lee el id con useParams
  • La página consulta GET /api/productos/:id con un efecto que depende del id y muestra foto, nombre, descripción completa y precio
  • Muestra "Cargando…" mientras espera y un mensaje con enlace de salida si el producto no existe o el id es inválido
  • El botón "Agregar al carrito" de la ficha suma al contador del Navbar
  • El modal tiene el enlace "Ver ficha completa" que lleva a la ficha del producto abierto, usando su _id
  • La pestaña del navegador muestra el nombre del producto y vuelve a "TechStore" al salir; la ficha tiene "Volver al catálogo", y recargarla con F5 conserva el producto
  • Sin errores en consola ni en la terminal de Vite, y sin scroll horizontal a 390px de ancho
