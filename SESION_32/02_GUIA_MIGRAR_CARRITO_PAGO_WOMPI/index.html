Paso 1 · Preparación

Las llaves de Wompi en tu .env

Wompi es la empresa que cobra con tarjeta, Nequi o PSE. Para que tu tienda hable con ella necesita cuatro valores secretos que Wompi te da solo a ti. Hoy trabajas en el modo de pruebas: todo funciona igual que en la vida real, pero no se mueve dinero de verdad.

1

Entra a tu cuenta de Wompi (comercios.wompi.co) y activa el modo de pruebas (también se llama *Sandbox*). Después abre la sección Desarrolladores y busca los cuatro valores. Si tu panel se ve distinto al de esta guía, pregúntale al instructor antes de seguir.

Nombre en tu .envEmpieza con…Para qué sirve
WOMPI_PUBLIC_KEYpub_test_Identifica tu comercio al abrir la ventana de pago. Es la única que viaja al navegador
WOMPI_PRIVATE_KEYprv_test_El servidor la usa para preguntarle a Wompi qué pasó con un pago
WOMPI_INTEGRITY_SECRETtest_integrity_Se mezcla con la referencia y el monto para firmar cada pago
WOMPI_EVENTS_SECRETtest_events_Para verificar avisos (webhooks) de Wompi. Hoy no se usa, pero queda guardado
Los secretos son tuyos. No los pegues en el chat, no los muestres en capturas de pantalla y nunca los subas a Git. Si se filtra uno, se genera otro en el panel de Wompi.
¿Y la "URL de Eventos" que aparece en ese panel? Es la dirección a la que Wompi avisa por su cuenta cuando cambia un pago (un *webhook*). Para eso necesita una dirección pública con https, y tu localhost no lo es. Hoy déjala vacía: tu tienda no espera ese aviso, sino que pregunta cada 3 segundos (Paso 6). El resultado es el mismo.
2

Abre backend/.env en VS Code. Las cuatro líneas de Wompi ya existen desde la sesión S18A. Reemplaza el valor de cada una por el de tu modo de pruebas, sin comillas y sin espacios alrededor del =:

WOMPI_PRIVATE_KEY=prv_test_xxxxxxxxxxxxxxxx
WOMPI_INTEGRITY_SECRET=test_integrity_xxxxxxxxxxxxxxxx
WOMPI_EVENTS_SECRET=test_events_xxxxxxxxxxxxxxxx
Las xxxx son un ejemplo: pega tus valores reales. Si alguna de las cuatro líneas no existe en tu archivo, agrégala.

El archivo .env se lee una sola vez, al encender el backend. Guardarlo no basta: en la terminal del backend pulsa Ctrl + C y vuelve a ejecutar:

Cómo verificar: la terminal del backend dice que conectó a MongoDB, sin errores. Y en .env las cuatro llaves empiezan con pub_test_, prv_test_, test_integrity_ y test_events_. Si alguna empieza con prod, es del modo real: cámbiala por la de pruebas.

Paso 2 · El hueco

Mira cómo se puede engañar al servidor

Antes de arreglar nada, vas a romperlo tú mismo. En la tienda no se puede hacer trampa porque los botones muestran el total correcto. Pero el servidor recibe peticiones de cualquiera, y con Postman se manda el cuerpo que se quiera.

1

Abre Postman y consigue tu token. Crea una petición POST a http://localhost:3000/api/auth/login, pestaña Body → raw → JSON, con tu correo y tu contraseña:

Postman — POST /api/auth/login — Body (raw, JSON)
{
  "email": "tu-correo@gmail.com",
  "password": "tu-contraseña"
}
Cómo verificar: la respuesta trae "token", un texto muy largo. Cópialo completo, sin las comillas: lo usas en el paso 3.
2

Necesitas el id de un producto. Abre en el navegador http://localhost:3000/api/productos y busca el primero (la MacBook): tiene "id": 1 y su precio "$8.999.000".

Dos "id" distintos. Cada producto tiene "id": 1 (un número corto que pusimos nosotros) y "_id": "66f2..." (el texto largo que crea MongoDB). Tu carrito ya guarda el número corto, y es el que se manda al pagar: el servidor se encarga de buscar el _id de MongoDB.
Cómo verificar: anotaste que la MacBook tiene "id": 1 y cuesta "$8.999.000".
3

Crea una segunda petición, POST a http://localhost:3000/api/pagos/firma. En la pestaña Authorization elige el tipo Bearer Token y pega tu token. En Body → raw → JSON manda un solo MacBook, pero con un total inventado:

Postman — POST /api/pagos/firma — Body (raw, JSON)
{
  "productos": [
    { "id": 1, "cantidad": 1 }
  ],
  "total": 1000
}

Pulsa Send y mira la respuesta:

respuesta del servidor (hoy)
{
  "reference": "TS-1731...",
  "amountInCents": 100000,
  "currency": "COP",
  "signature": "a3f9...",
  "publicKey": "pub_test_..."
}
Cómo verificar: amountInCents vale 100000 centavos, o sea $1.000. Una MacBook de $8.999.000 quedó firmada por mil pesos. Esa firma es válida: Wompi la aceptaría y cobraría $1.000.
Eso es un hueco de seguridad. El servidor le cree al navegador el total que le manda. Es el mismo principio de S30, cuando el registro aceptaba "rol": "admin": todo lo que llega desde el navegador se puede alterar. En el siguiente paso lo arreglas.
Paso 3 · El servidor calcula

El total sale de la base de datos

La solución: el navegador solo dice qué productos y cuántos. El servidor busca cada precio en la base de datos, multiplica por la cantidad y suma. Si el cuerpo trae un total, se ignora.

    // 1. Referencia única para esta transacción

    const signature = crypto.createHash('sha256').update(raw).digest('hex');

    // 3. Guardar datos del carrito en la Transaccion con estado PENDING

      wompiReference: reference, amountInCents, currency,
      status: 'PENDING',
      pendingOrderData: { usuario: req.usuario.id, productos, total }
    });

    // 4. Devolver datos al Widget de Wompi en el frontend
    res.json({
      reference, amountInCents, currency, signature,
      publicKey: process.env.WOMPI_PUBLIC_KEY
    });

  } catch (err) {
    console.error(err);
    res.status(500).json({ error: 'Error al generar la firma' });
  }
});

// Crea la Orden cuando Wompi confirma un pago APPROVED (usada por el polling y por el webhook)
async function confirmarAprobado(transaccion, wompiTx) {
  transaccion.status = wompiTx.status;
  transaccion.wompiTransactionId = wompiTx.id;

  if (wompiTx.status === 'APPROVED' && !transaccion.orden) {
    const pod = transaccion.pendingOrderData;
    const orden = await Orden.create({
      usuario: pod.usuario, productos: pod.productos, total: pod.total,
      wompiTransactionId: wompiTx.id, wompiReference: wompiTx.reference,
      estado: 'PAGO_CONFIRMADO'
    });
    transaccion.orden = orden._id;
  }

  await transaccion.save();
}

// (cuando hay servidor público). En desarrollo local el polling cubre esta función.
router.post('/webhook', async (req, res) => {
  const { signature, timestamp, data } = req.body;
  const secret = process.env.WOMPI_EVENTS_SECRET;
  if (!secret) return res.status(200).json({ ok: true }); // sin secreto → modo dev, ignorar

  const tx = data?.transaction;
  if (!tx) return res.status(400).json({ error: 'Payload inválido' });

  // Verificar firma del webhook (fórmula oficial Wompi)
  const props = (signature?.properties || []).map((prop) => {
    const path = prop.split('.').slice(1);
    let v = tx; for (const k of path) v = v?.[k]; return v;
  }).join('');

  const computed = crypto.createHash('sha256')
    .update(`${props}${timestamp}${secret}`).digest('hex');
  if (computed !== signature?.checksum) return res.status(400).json({ error: 'Firma inválida' });

  const transaccion = await Transaccion.findOne({ wompiReference: tx.reference });
  if (!transaccion) return res.status(404).json({ error: 'Transacción no encontrada' });

  await confirmarAprobado(transaccion, tx);
  res.json({ ok: true });
});

Pagar no es instantáneo: Wompi tarda unos segundos en confirmar con el banco. La página nueva, /pago/:referencia, le pregunta al servidor cada 3 segundos qué pasó y, cuando hay respuesta, la muestra. Es el efecto más completo de la fase: arranca un reloj, y sabe detenerlo.

import { useState, useEffect, useContext } from "react";
import { useParams, Link } from "react-router-dom";
import { CartContext } from "../context/CartContext.jsx";

// Qué se muestra para cada estado del pago
const MENSAJES = {
  PENDING: { titulo: "Confirmando tu pago", texto: "Estamos esperando la respuesta de Wompi. No cierres esta página." },
  APPROVED: { titulo: "Pago aprobado", texto: "Tu compra quedó registrada y tu carrito está vacío." },
  DECLINED: { titulo: "Pago rechazado", texto: "El banco no aprobó el pago. Tu carrito sigue como estaba: puedes intentar con otro medio de pago." },
  ERROR: { titulo: "El pago no se pudo completar", texto: "Hubo un error en el proceso. Tu carrito sigue como estaba." },
  VOIDED: { titulo: "El pago fue anulado", texto: "La transacción se anuló. Tu carrito sigue como estaba." },
  TIMEOUT: { titulo: "Todavía no tenemos respuesta", texto: "No pudimos confirmar el pago en un minuto. Si cerraste la ventana sin pagar, tu carrito sigue como estaba." },
};

function PagoResultado() {
  const { referencia } = useParams();
  const { vaciarCarrito } = useContext(CartContext);
  const [estado, setEstado] = useState("PENDING");

  // Pregunta al servidor cada 3 segundos, hasta 20 veces (un minuto)
  useEffect(() => {
    let intentos = 0;
    const intervalo = setInterval(async () => {
      intentos++;
      if (intentos > 20) {
        clearInterval(intervalo);
        setEstado("TIMEOUT");
        return;
      }
      try {
        const respuesta = await fetch("http://localhost:3000/api/pagos/estado/" + referencia, {
          headers: { Authorization: "Bearer " + localStorage.getItem("token") },
        });
        const datos = await respuesta.json();
        if (datos.status && datos.status !== "PENDING") {
          clearInterval(intervalo);
          setEstado(datos.status);
        }
      } catch (error) {
        console.error("No se pudo consultar el pago", error);
      }
    }, 3000);

    // Limpieza: si la persona se va de la página, el reloj se detiene
    return () => clearInterval(intervalo);
  }, [referencia]);

  // Cuando el pago se aprueba, el carrito se vacía
  useEffect(() => {
    if (estado === "APPROVED") vaciarCarrito();
  }, [estado]);

  const mensaje = MENSAJES[estado] || MENSAJES.ERROR;

  return (
    <section className="max-w-md mx-auto text-center flex flex-col items-center gap-5 py-16">
      <p className="font-mono text-xs uppercase tracking-widest text-gray-500">Pago</p>
      <h1 className="font-display font-bold text-4xl tracking-tighter">
        {mensaje.titulo}
        <span className="text-accent">.</span>
      </h1>
      <p className="text-gray-700">{mensaje.texto}</p>
      <p className="font-mono text-xs text-gray-500">Referencia: {referencia}</p>

      {estado === "APPROVED" && (
        <Link
          to="/productos"
          className="bg-ink text-paper px-6 py-3 rounded-card text-sm font-semibold hover:bg-accent transition-colors"
        >
          Seguir comprando
        </Link>
      )}
      {estado !== "PENDING" && estado !== "APPROVED" && (
        <Link
          to="/carrito"
          className="bg-ink text-paper px-6 py-3 rounded-card text-sm font-semibold hover:bg-accent transition-colors"
        >
          Volver al carrito
        </Link>
      )}
    </section>
  );
}

export default PagoResultado;
ParteQué hace
const MENSAJES = { ... }Una tabla que dice qué título y qué texto mostrar para cada estado del pago. Está fuera del componente porque no cambia nunca
useParams()Lee la parte variable de la dirección. En /pago/TS-1731-4821, referencia vale "TS-1731-4821". Se llama igual que en la ruta: :referencia
useState("PENDING")El estado empieza en "pendiente" y cambia cuando el servidor da una respuesta
setInterval(async () => { ... }, 3000)Repite la función de adentro cada 3000 milisegundos, o sea cada 3 segundos
intentos > 20Un tope: 20 veces por 3 segundos son 60 segundos. Pasado ese tiempo, se rinde y pone "TIMEOUT" (se acabó el tiempo)
datos.status && datos.status !== "PENDING"Solo reacciona si el servidor devolvió un estado y ese estado ya no es "pendiente". Si el servidor responde con un error sin status, la página sigue esperando en vez de romperse
clearInterval(intervalo)Detiene el reloj. Se llama en cuanto hay respuesta, así no se sigue preguntando
return () => clearInterval(intervalo)La limpieza del efecto: si la persona se va de la página, el reloj se detiene. Sin esto seguiría preguntando para siempre, en una página que ya no existe
[referencia]El efecto depende de la referencia: si cambiara, se reinicia con la nueva
El segundo useEffectCuando el estado pasa a "APPROVED", llama a vaciarCarrito(). El carrito solo se vacía si el pago se aprobó
MENSAJES[estado] || MENSAJES.ERRORBusca el mensaje del estado actual. Si llegara un estado que no conocemos, usa el de error en vez de mostrar una página vacía
¿Por qué los estados en inglés? APPROVED, DECLINED y los demás son las palabras que usa Wompi, y el servidor los reenvía tal cual. Solo TIMEOUT es nuestro.
