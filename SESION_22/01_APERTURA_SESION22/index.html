El problema que ya tienes en tu proyecto

En App.jsx hay 3 bloques de tarjeta de producto — mismo HTML, mismas clases, solo cambia el texto:

App.jsx — estado actual (código real de tu proyecto)
1<div className="flex flex-col gap-2 p-4 rounded-xl shadow-md bg-white">
2 <h3>Mouse Inalámbrico</h3>
3 <p>$89.900</p>
4</div>
5
6<div className="flex flex-col gap-2 p-4 rounded-xl shadow-md bg-white">
7 <h3>Teclado Mecánico</h3>
8 <p>$149.900</p>
9</div>
10{/* ...y una 3ra vez más, para el Monitor 24" */}
❌ Por qué esto es un problema
Si mañana cambia el diseño de la tarjeta (ej. agregar una etiqueta "Nuevo"), hay que editarlo 3 veces — y si el catálogo real tiene 50 productos (como lo tendrá cuando se conecte al backend en S24), serían 50 copias del mismo bloque. Un solo error de tipeo en una copia, y esa tarjeta se ve distinta a las demás.
⚠️ No es un error de S20-S21
Para 3 tarjetas de práctica, copiar y pegar fue la forma más simple de avanzar. El problema aparece al escalar — y React tiene una solución exacta para esto: un componente que recibe datos diferentes cada vez que se usa.

Concepto

Props — datos que entran a un componente

"Props" es la forma corta de decir properties (propiedades). Son la manera en que un componente padre le pasa información a un componente hijo — igual que los atributos de una etiqueta HTML.

<ProductCard
  nombre="Mouse"
  precio="$89.900"
/>
→
🖱️ Mouse — $89.900
⌨️ Teclado — $149.900
🖥️ Monitor — $899.900
📨
Se pasan como atributos
Igual que <img src="..." /> — cada atributo que escribas dentro de <ProductCard nombre="..." /> es una prop.
📥
El componente las recibe como parámetro
function ProductCard(props) — props es un objeto con todo lo que se le pasó.
🔒
Son de solo lectura
El componente hijo nunca modifica sus props — solo las usa para mostrar algo. Eso se aprende a cambiar con useState en S23.
✅ La idea clave de hoy
Un solo componente ProductCard, usado 3 veces con props distintas, reemplaza 3 bloques de JSX casi idénticos. El componente es el "molde"; las props son lo que cambia en cada copia.
06 / 13
Concepto

Usar props dentro del JSX con { }

Dentro del componente, cada prop se inserta en el JSX con llaves — el mismo { } que se vio en la Sesión 21 para mezclar JavaScript con HTML.

src/ProductCard.jsx (nuevo archivo de hoy)
1function ProductCard(props) {
2return (
3 <div>
4 <h3>{props.nombre}</h3>
5 <p>{props.precio}</p>
6 </div>
7)
8}
ParteQué significa
function ProductCard(props)El parámetro props recibe automáticamente todos los atributos que se le pasaron al usar <ProductCard />
props.nombreAccede al valor de la prop nombre — igual que acceder a cualquier propiedad de un objeto en JavaScript
{ } alrededor de props.nombreObligatorio — sin las llaves, JSX lo trataría como texto literal, no como código JavaScript
💡 ¿Por qué se llama "props" y no "parámetros"?
Técnicamente sí es un parámetro de la función — "props" es solo el nombre que la comunidad de React usa por convención, porque ese parámetro siempre contiene las "propiedades" que el componente padre le pasó.

Concepto

Los datos viven en un array, no en el JSX

En vez de escribir 3 veces <ProductCard nombre="..." precio="..." />, los 3 productos se guardan en un array de objetos de JavaScript — la misma forma en que el backend real los entrega.

App.jsx — array de productos
1const productos = [
2 { nombre: "Mouse Inalámbrico", precio: "$89.900" },
3 { nombre: "Teclado Mecánico", precio: "$149.900" },
4 { nombre: "Monitor 24\"", precio: "$899.900" },
5];
✅ Por qué esto importa para después
Cuando en la Sesión 24 se conecte el catálogo a GET /api/productos, el backend va a devolver exactamente esto — un array de objetos. Lo que se practica hoy con datos de prueba es la misma estructura que se usará con datos reales.

Concepto

.map() — de un array de datos a un array de componentes

.map() ya se usó en la Sesión 5 (Fase 2) para transformar productos en texto HTML. Hoy se usa para transformar productos en componentes <ProductCard />.

App.jsx — dentro del return
1<section className="grid ...">
2 {productos.map((p) => (
3 <ProductCard key={p.nombre} nombre={p.nombre} precio={p.precio} />
4 ))}
5</section>
❌ Antes de hoy
3 bloques de JSX escritos a mano — agregar un producto 4 significa copiar y pegar un bloque entero.
VS
✅ Con .map()
1 línea de JSX que se repite sola — agregar un producto 4 significa solo agregar un objeto al array.
09 / 13
Concepto

key — el identificador que React necesita

Cuando se genera una lista de componentes con .map(), React exige una prop especial llamada key en cada elemento — no es opcional.

🔑
¿Para qué sirve?
Le permite al Virtual DOM (visto en S21) identificar cuál tarjeta es cuál entre renders — así sabe exactamente qué actualizar si la lista cambia, sin recrear las que no cambiaron.
🆔
Debe ser único entre hermanos
Dos tarjetas en la misma lista no pueden tener el mismo key — por eso hoy se usa p.nombre (cada producto tiene nombre distinto).
🚫
No se usa dentro del componente
key es solo para React — no llega como prop normal, props.key no existe dentro de ProductCard.
⚠️ Si se te olvida el key
El catálogo igual se ve bien en pantalla — pero la consola del navegador muestra una advertencia amarilla: Warning: Each child in a list should have a unique "key" prop. No rompe nada hoy, pero sí puede causar bugs reales más adelante, cuando la lista cambie dinámicamente (S23 en adelante).
