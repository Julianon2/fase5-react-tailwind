Paso 1 · Componente

Crear src/ProductCard.jsx

Mismo primer paso que con Navbar.jsx en S21: crear el archivo, mover el JSX de una tarjeta, y envolverlo en una función — pero esta vez, con props en vez de texto fijo.

1

En src/, crear el archivo ProductCard.jsx (al lado de App.jsx y Navbar.jsx).

2

En App.jsx, cortar (Ctrl+X) el bloque completo de una de las 3 tarjetas (cualquiera, por ejemplo la del Mouse) y pegarlo (Ctrl+V) dentro de ProductCard.jsx. Las otras 2 tarjetas se borran en el Paso 3 — por ahora déjalas donde están.

Bloque que se mueve de App.jsx a ProductCard.jsxcortar y pegar

  <h3 className="font-bold text-lg">Mouse Inalámbrico</h3>
  <p className="text-texto-dim text-sm">Mouse ergonómico, conexión Bluetooth</p>
  <p className="text-verde font-extrabold">$89.900</p>

3

Ese bloque que acabas de pegar tiene los datos del Mouse escritos a mano (Mouse Inalámbrico, $89.900, etc.) — pero ProductCard no debe quedar fijo a un solo producto, porque el Paso 3 lo va a reutilizar para los 3 productos del catálogo (y más adelante, para cualquier cantidad que venga del backend).

Por eso, en vez de dejar el texto fijo, la estructura cambia: cada dato (nombre, descripción, precio, imagen) se reemplaza por una prop genérica — un "espacio en blanco" que se llena distinto cada vez que el componente se use. Reescribe ProductCard.jsx para que quede exactamente así, envuelto en una función que recibe props:

frontend-react/src/ProductCard.jsxestructura final (sin export todavía)
function ProductCard(props) {
  return (
    <div className="flex flex-col gap-2 p-4 rounded-xl shadow-md bg-white">
      <img src={props.imagen} className="rounded-lg" />
      <h3 className="font-bold text-lg">{props.nombre}</h3>
      <p className="text-texto-dim text-sm">{props.descripcion}</p>
      <p className="text-verde font-extrabold">{props.precio}</p>
    </div>
  )
}

Lo que cambió respecto al bloque que pegaste:

Antes (texto fijo del Mouse)Ahora (prop genérica)
src="https://placehold.co/300x200"src={props.imagen}
Mouse Inalámbrico{props.nombre}

ParteQué significa
function ProductCard(props)El parámetro props llega automáticamente con todo lo que se le pase al usar <ProductCard />
props.imagenProp nueva, además de nombre/descripcion/precio — reemplaza la URL fija "https://placehold.co/300x200", así cada producto puede tener su propia imagen (hoy las 3 comparten la misma URL de prueba, pero la prop ya queda lista para cuando cada producto real tenga su propia foto)
src={props.imagen}En un atributo normal de HTML, las llaves reemplazan las comillas — el valor viene de JavaScript, no es texto fijo
{props.nombre}Dentro del contenido de una etiqueta, las llaves insertan el valor de la prop
💡En el Paso 3 vas a ver de dónde sale cada prop: props.nombre, props.imagen, etc. van a recibir los datos del Mouse, del Teclado o del Monitor según cuál producto se esté dibujando en ese momento — el mismo componente, con datos distintos cada vez.

Paso 3 · Renderizado

Reemplazar las 3 tarjetas por productos.map()

Ahora se borran las 3 tarjetas escritas a mano (o las 2 que quedaron, si ya moviste una al Paso 1) y se reemplazan por una sola línea que las genera automáticamente.

1

Dentro del <section className="grid ...">>, borrar las 3 tarjetas (o las que te queden) y escribir en su lugar:

frontend-react/src/App.jsxreemplazar el contenido del section
<section className="grid grid-cols-1 md:grid-cols-2 lg:grid-cols-3 gap-6">
  {productos.map((p) => (
    <ProductCard
      key={p.nombre}
      nombre={p.nombre}
      descripcion={p.descripcion}
      precio={p.precio}
      imagen={p.imagen}
    />
  ))}
</section>
ParteQué significa
{productos.map((p) => ( ... ))}Recorre el array; por cada objeto "p", genera el JSX que está entre paréntesis
key={p.nombre}Identificador único exigido por React — aquí se usa el nombre porque no se repite entre productos
nombre={p.nombre}Pasa el valor real de ese producto como prop — no es el mismo "nombre" de ambos lados por coincidencia, es intencional: la prop se llama igual que la propiedad del objeto
💡El nombre de la prop (izquierda del =) y el nombre de la propiedad del objeto (p.algo, derecha del =) no tienen que llamarse igual — aquí coinciden a propósito, para que sea más fácil de leer.
✅Cómo verificar: en localhost:5173, el catálogo se ve exactamente igual que antes — 3 tarjetas con las mismas imágenes, nombres y precios. El cambio es invisible a simple vista, pero ahora viene de datos, no de JSX repetido.
Paso 4 · Verificación

Confirmar que todo sigue funcionando

El objetivo de hoy no es cambiar el diseño — es que el mismo catálogo se genere a partir de datos.

1

Abrir localhost:5173: el catálogo debe verse igual que en S20-S21 — 3 tarjetas, mismos textos y precios.

2

Abrir la consola del navegador (F12 → Console). No debe aparecer la advertencia amarilla de key, ni errores rojos.

⚠️Si ves Warning: Each child in a list should have a unique "key" prop, revisa que el key={p.nombre} esté escrito dentro de <ProductCard>, no dentro de .map() por fuera del componente.
3

Prueba real de que .map() funciona: agregar temporalmente un cuarto objeto al array productos (copiando la estructura de uno existente, con datos inventados) y guardar — debe aparecer una 4ta tarjeta sola, sin tocar el <section> para nada. Después puedes borrar ese objeto de prueba si no lo quieres dejar.

✅Cómo verificar: la 4ta tarjeta aparece automáticamente en el grid — esa es la prueba de que agregar un producto ya no requiere escribir JSX nuevo, solo agregar un dato.
