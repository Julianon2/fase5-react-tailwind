SLIDE 04 / 16
Punto de partida

Todo vive en Atlas

Hoy server.js lee una sola variable, MONGODB_URI, que apunta a tu cluster en la nube. Funciona, pero tiene tres costos que van a crecer en las próximas sesiones.

Depende de internet
Sin conexión estable, el backend no arranca. En el aula de Garzón eso puede pasar en el peor momento.
Datos de prueba en producción
En S30 se crean usuarios reales y en S32 pagos de prueba. Cada prueba llena Atlas de registros que luego hay que limpiar a mano.
Miedo a borrar
Una base compartida o en la nube se cuida. Una base propia se puede romper y rehacer, que es como se aprende.
Lo que ya funciona
Mongoose, los modelos, las rutas y el frontend no cambian. Solo cambia a dónde se conecta el backend.
Cada aprendiz tiene su propio Atlas
Cada uno trabaja con su propio cluster y sus propios productos. Por eso la base local no se copia de nadie: se crea con un script desde el archivo productos.json que todos tienen en frontend/data/.
SLIDE 05 / 16
Concepto · Entornos

Dos entornos, dos bases

Un proyecto serio no prueba sobre lo que usan los clientes. Se separan dos mundos con el mismo código y bases distintas.

Local — desarrollo
Vive en tu computador. Gratis, rápida, sin internet. Es el campo de pruebas: aquí se registra "usuario1@prueba.com" mil veces y no pasa nada.
≠
Atlas — producción
Vive en la nube. Es la que ve el mundo cuando el proyecto se publica. Se cuida: solo debe tener datos que importan.
El mismo código
Mongoose, los modelos y las rutas son idénticos. Lo único distinto es la dirección de la base, y esa dirección vive en el archivo .env.
Por eso existe .env
Es el lugar para lo que cambia según el computador: direcciones, contraseñas, claves. Nunca se sube a GitHub (ya está en .gitignore).
Un interruptor
Una variable, DB_MODO, dice cuál de las dos direcciones usa el backend al arrancar.
SLIDE 06 / 16
Concepto · Cadena de conexión

La dirección de una base de datos

Mongoose se conecta con un texto llamado cadena de conexión. La de tu Atlas y la de tu base local se parecen, pero tienen diferencias que importan.

.env — las dos cadenas
1MONGODB_URI_ATLAS=mongodb+srv://usuario:clave@cluster0.abcde.mongodb.net/techstore
2MONGODB_URI_LOCAL=mongodb://127.0.0.1:27017/techstore
La cadena local, pieza por pieza
1mongodb://127.0.0.1:27017/techstore
// las 3 piezas, en palabras normales
127.0.0.1 = este mismo computador  ·  27017 = el puerto en el que escucha MongoDB  ·  techstore = el nombre de la base de datos
↓ ↓ ↓
"Conéctate a este computador, por el puerto 27017, y usa la base techstore."
ParteQué significa
mongodb+srv://Es el formato de Atlas: busca la dirección real del cluster por DNS y usa conexión cifrada. Lleva usuario y contraseña
mongodb://Formato clásico, el de una base local. En desarrollo no lleva usuario ni contraseña
127.0.0.1La dirección de "este mismo computador". Siempre funciona. localhost normalmente también, pero con algunas versiones de Node (17 a 19) se resuelve a la dirección IPv6 y MongoDB, por defecto, solo atiende IPv4
/techstoreEl nombre de la base. Si no existe, se crea sola: el backend la crea al conectarse, junto con una colección vacía por cada modelo
SLIDE 07 / 16
Concepto · Compass

Ver la base de datos con los ojos

Hasta ahora la base de datos era invisible: se llenaba y se leía desde el código. MongoDB Compass es la herramienta gráfica oficial: se conecta a una base y la muestra como carpetas.

Conexión — mongodb://127.0.0.1:27017
↓ contiene ↓
Base de datos — techstore
↓ contiene ↓
Colecciones — productos, usuarios, mensajes, ordens, transaccions
↓ contienen ↓
Documentos — cada producto, cada usuario
Es la misma jerarquía que ya conoces de Mongoose: modelo Producto → colección productos → un documento por producto. Mongoose pone los nombres en plural, en inglés: de ahí "ordens".
Ver
Cada documento aparece con sus campos. Puedes buscar con un filtro, por ejemplo { nombre: "iPhone 15 Pro" }.
Editar
Cambia un precio directamente en un documento y recarga el catálogo: el cambio se ve de inmediato.
Exportar e importar
Saca una colección a un archivo JSON, o mete uno a otra base. Es el puente entre local y Atlas.
Con poder viene cuidado
En Compass se puede borrar una colección entera con dos clics. Antes de borrar o editar, mira a qué conexión estás conectado. Por eso se le pone nombre y color a cada una: TechStore Local en verde y TechStore Atlas en rojo. Compass además muestra una laptop para la local y un servidor para Atlas.
SLIDE 08 / 16
Práctica · Una línea que elige

Del .env a la conexión

server.js lee una variable y decide a qué base conectarse. Es el cambio de código más pequeño de la sesión.

.env — el interruptor
1DB_MODO=local
2MONGODB_URI_LOCAL=mongodb://127.0.0.1:27017/techstore
3MONGODB_URI_ATLAS=mongodb+srv://usuario:clave@cluster0.abcde.mongodb.net/techstore
server.js — la línea que elige
1const uri = process.env.DB_MODO === "local"
2 ? process.env.MONGODB_URI_LOCAL
3 : process.env.MONGODB_URI_ATLAS
// las 4 piezas, en palabras normales
process.env.DB_MODO = lo que diga el .env  ·  "local" = el valor que activa la base local  ·  process.env.MONGODB_URI_LOCAL = la dirección si es local  ·  process.env.MONGODB_URI_ATLAS = la dirección en cualquier otro caso
↓ ↓ ↓ ↓
"Si el .env dice local, usa la base de tu computador; si no, Atlas."
ParteQué hace
process.env.NOMBRELee una variable del archivo .env (la carga dotenv en la primera línea de server.js)
condición ? A : BEl operador ternario que ya conoces de React: si la condición es cierta, A; si no, B
Atlas por defectoCualquier valor distinto de "local" (o ninguno) usa Atlas, que es lo que el proyecto ha hecho hasta hoy. Así nada se rompe si alguien olvida la variable
Se reinicia el servidorEl .env se lee solo al arrancar, y nodemon no lo vigila: tras cambiar DB_MODO escribe rs y Enter en la terminal del backend (o Ctrl + C y npm run dev)
SLIDE 09 / 16
Práctica · Cambiar de entorno

La rutina de tres pasos

Cambiar de base de datos es siempre igual, y no toca el código. La vas a repetir muchas veces: aprenderla bien es el objetivo central de la sesión.

1
Interruptor
Cambiar el .env
En backend/.env escribe DB_MODO=local o DB_MODO=atlas y guarda con Ctrl + S.
2
Reinicio
Reiniciar el backend
En la terminal del backend escribe rs y pulsa Enter. Sin este paso, el cambio no se aplica.
3
Confirmación
Leer el mensaje
La terminal dice Conectado a MongoDB (local) o (atlas). Si no coincide con lo que escribiste, falta reiniciar.
El ciclo completo, de principio a fin
1# 1) backend/.env
2DB_MODO=local # o atlas
3
4# 2) en la terminal del backend: rs y Enter
5rs
6
7# 3) la terminal responde
8 Conectado a MongoDB (local)
El error más común
Cambiar el .env y olvidar reiniciar. nodemon reinicia solo cuando cambia un archivo de código, pero no vigila el .env: el backend sigue usando la base de antes y todo "parece" no funcionar. La señal: el mensaje de la terminal no coincide con lo que escribiste.
SLIDE 10 / 16
Concepto · Saber dónde estás

Siempre debes saber en cuál estás

Trabajar en el entorno equivocado es el error más caro: borrar datos reales creyendo que eran de prueba. Hay tres señales, de la más rápida a la más completa.

1 · El mensaje de arranque
La terminal del backend, al iniciar: Conectado a MongoDB (local) o (atlas).
2 · La ruta de prueba
Abre localhost:3000 en el navegador: la respuesta incluye "baseDeDatos": "local" o "atlas".
3 · El ícono y el color en Compass
TechStore Local lleva una laptop y color verde; TechStore Atlas, un servidor y color rojo: de un vistazo sabes en cuál base estás mirando.

Concepto · Datos iniciales

Una base vacía necesita sembrarse

La base local nace vacía. Un seed (semilla) es un script que la llena con datos iniciales conocidos, las veces que haga falta.

backend/seed.js — la idea
1const productos = require("../frontend/data/productos.json")
2
3await Producto.deleteMany({})
4await Producto.insertMany(productos)
5console.log("Productos sembrados:", productos.length)
Repetible
Primero borra lo que hay y luego inserta. Correrlo dos veces deja 6 productos, no 12. Si algo se daña, se vuelve a correr.
Con freno de seguridad
El seed borra datos. Por eso se niega a correr si DB_MODO no es "local": así nunca se ejecuta por error contra Atlas.
Los _id cambian
Cada vez que se siembra, Mongo crea _id nuevos. Las direcciones /productos/<_id> de S29 guardadas en favoritos dejan de servir; es normal.
SLIDE 12 / 16
Concepto · Mover datos

Llevar datos de una base a otra

Las dos bases no se hablan entre sí: para mover información hay que sacarla a un archivo y meterla en el otro lado. Compass lo hace con dos botones.

Base local — colección productos
↓ Export collection → productos.json ↓
Archivo productos.json
↓ Import data (conectado a Atlas) ↓
Atlas — colección nueva
En la práctica de hoy se importa a una colección de prueba, no a la real.
Importar duplica
Si importas sobre la colección productos de Atlas sin vaciarla antes, tendrás cada producto dos veces. Hoy se usa una colección nueva para no tocar lo real.
Los usuarios no viajan solos
Una cuenta creada en la base local no existe en Atlas, y viceversa. Cada base tiene su propia colección usuarios.
Existe una vía profesional
mongodump y mongorestore (las "Database Tools") hacen lo mismo para bases enteras desde la terminal. Hoy usamos Compass; es lo mismo, con botones.

Antes de empezar

Prerrequisitos

La sesión instala dos programas nuevos. Tu proyecto debe estar como quedó en S29.

Backend y frontend funcionando
backend/ con npm run dev conectado a tu Atlas, y frontend-react/ con npm run dev en localhost:5173, como en S29. Son dos terminales abiertas a la vez. Si hoy no conecta, resuélvelo primero.
Atlas y Compass de la S10
Tu cluster, tu usuario y tu conexión de Atlas en Compass, y la cadena que ya tienes en MONGODB_URI (S12). No se cambian: se renombran. La guía empieza verificando todo esto; si algo falta, te dice cómo hacerlo.
Permiso para instalar
Instalar MongoDB Community Server pide permisos de administrador en Windows y la contraseña del computador en Mac. Compass ya lo tienes instalado; si no, la guía te dice cómo.
Espacio y paciencia
Cerca de 1 GB libre. La descarga y la instalación son lo más lento de la sesión: se hacen primero.
Windows y Mac
La guía trae los pasos de los dos sistemas. En Windows el servidor queda como un servicio que arranca solo; en Mac se instala con Homebrew y se inicia con un comando. Instala la versión 7.0 o superior.

Cierre · Sesión extra

¡Empezamos!

Criterios de evaluación
  • MongoDB Community Server 7.0 o superior instalado y corriendo, y Compass conectado a mongodb://127.0.0.1:27017
  • El archivo .env tiene DB_MODO, MONGODB_URI_LOCAL y MONGODB_URI_ATLAS, y server.js elige la dirección según DB_MODO
  • El mensaje de arranque del backend dice a qué base se conectó, y localhost:3000 lo confirma con el campo baseDeDatos
  • Sabes cambiar de entorno (cambiar DB_MODO, reiniciar con rs y confirmar) y decir en cuál estás por tres señales distintas
  • npm run seed deja 6 productos en la base local y se niega a correr si DB_MODO no es local
  • Con DB_MODO=local el catálogo de la tienda muestra los productos de la base local, y un precio cambiado en Compass se refleja en la tienda sin tocar Atlas
  • Con DB_MODO=atlas el catálogo vuelve a mostrar los datos de Atlas, sin cambiar código
  • Una colección exportada de la base local aparece importada en tu Atlas, en una colección de prueba
