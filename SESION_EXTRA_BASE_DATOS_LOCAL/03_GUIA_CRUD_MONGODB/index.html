Paso 0 · Preparación

Antes de tocar datos: la regla de oro y las herramientas

Crear, leer, actualizar y borrar (CRUD) son las cuatro operaciones con las que se maneja cualquier base de datos. Hoy las practicas sobre tu propio proyecto: el catálogo de TechStore (productos) y la bandeja del formulario de contacto (mensajes). Borrar y editar no tiene papelera, por eso todo se hace en tu base local, que puedes restaurar con un comando.

1

Comprueba que tienes todo listo. Es la rutina de la sesión extra: dos servidores corriendo y la base local activa.

ComprobaciónCómoQué debes ver
El servidor de MongoDBWindows: Get-Service MongoDB. Mac: brew services listRunning (Windows) o started (Mac)
El backend en modo localEn backend/: npm run dev. Abre localhost:3000 en el navegador"baseDeDatos":"local"
El frontendEn frontend-react/: npm run dev. Abre localhost:5173/productosLos 6 productos de siempre
La conexión de CompassEn Compass, la conexión TechStore Local (verde, ícono de laptop) → techstore → productos6 documentos
Regla de oro: todo lo de esta guía se hace en TechStore Local (verde, laptop) y con DB_MODO=local. Nunca en TechStore Atlas (rojo, servidor): ahí no existe npm run seed para deshacer. Antes de cada comando mira en qué conexión estás. Si algo sale mal en local, npm run seed vuelve a dejar los 6 productos originales.
2

Abre la consola de comandos de Compass. Es la misma ventana, no hay que instalar nada aparte. Pulsa el ícono >_ que aparece junto a TechStore Local al pasar el mouse (o el botón Open MongoDB shell, arriba a la derecha). Se abre una pestaña nueva, ya conectada a tu base local. Escribe:

consola de Compass (mongosh)
use("techstore")
db.productos.countDocuments()
ParteQué hace
use("techstore")Elige la base con la que vas a trabajar (si abriste la consola desde dentro de la base, ya viene elegida)
dbSignifica "la base activa". Es el punto de partida de todos los comandos
db.productosLa colección productos de esa base: el catálogo de la tienda
.countDocuments()La operación: contar los documentos. Para cada acción cambia el método
Cómo verificar: la consola responde 6: los 6 productos del seed. Si responde otro número o da error, revisa en la parte de arriba que estás conectado a TechStore Local y que hiciste el seed.
3

Estas son las cuatro operaciones, con lo que ya conoces de SQL y dónde se hace cada una en Compass:

OperaciónEn SQLEn la consola (mongosh)En Compass con botones
C · Create (crear)INSERT INTO productos ...insertOne({...}) y insertMany([...])ADD DATA ▾ → Insert document
R · Read (leer)SELECT * FROM productos WHERE ...find({ filtro })La barra Filter de la colección
U · Update (actualizar)UPDATE productos SET ... WHERE ...updateOne({ filtro }, { $set: {...} })El lápiz de cada documento, luego Update
D · Delete (borrar)DELETE FROM productos WHERE ...deleteOne({ filtro })El ícono de papelera del documento
El ciclo de tres tiempos. Con Update y Delete nunca actúes a ciegas. Hazlo siempre así: 1) buscar el documento (para ver cómo está), 2) actuar (cambiarlo o borrarlo) y 3) buscar de nuevo (para confirmar). Y filtra siempre por un identificador único, nunca por un texto libre que pueda repetirse.
Tienes dos identificadores. id es el número del catálogo (1, 2, 3…): el de "REF 01" en la tarjeta y el que usa el carrito. _id es el que crea MongoDB solo: el que lleva la dirección de la ficha de S29 (/productos/<_id>). Los dos sirven para filtrar; en esta guía usarás sobre todo id.
En la barra Filter de Compass no se escribe db.productos.find(...): la barra ya sabe que es un find sobre esa colección, así que solo se pega el objeto que va entre los paréntesis. Por ejemplo, para find({ id: 7 }) en la barra escribes { id: 7 } y pulsas Find.
Paso 1 · Create

Crear productos nuevos

Agregarás productos al catálogo sin escribir una sola línea de la tienda: el frontend ya lee todo lo que haya en la colección. Mira la tienda en localhost:5173/productos después de cada comando.

1

Inserta un producto con insertOne. Copia el comando completo en la consola y pulsa Enter:

consola de Compass (mongosh)
db.productos.insertOne({
  id: 7,
  icono: "🖱️",
  nombre: "Mouse Logitech MX Master 3S",
  descripcion: "Sensor de 8000 DPI, scroll silencioso y 7 botones programables.",
  precio: "$399.000",
  imagen: "https://images.unsplash.com/photo-1527864550417-7fd91fc51a46?w=400&h=250&fit=crop&q=80"
})
ParteQué hace
db.productos.insertOne({ ... })Guarda un documento nuevo en la colección productos
id: 7Un número, sin comillas: es el siguiente después de los 6 que ya existen
icono, nombre, descripcion, imagenTexto, entre comillas. Son los mismos campos que tienen los productos del seed
precio: "$399.000"También texto entre comillas, con el formato de los demás ("$8.999.000"). Así lo guarda el modelo Producto y así lo lee la tienda
_idNo lo escribes: MongoDB lo crea solo
Cómo verificar: la consola responde algo como { acknowledged: true, insertedId: ObjectId('…') }. db.productos.countDocuments() ahora da 7. Recarga localhost:5173/productos (F5): aparece la tarjeta del Mouse Logitech y la tienda muestra 7 productos.

3

Lo mismo con botones. En Compass abre techstore → productos, pulsa ADD DATA ▾ → Insert document y pulsa el ícono de llaves { } de la esquina superior derecha para pasar a modo texto (JSON). Borra lo que haya y pega un solo objeto (sin db.productos.insertOne( ni el paréntesis final), por ejemplo:

4

Experimento: ¿MongoDB revisa que el documento esté completo? Inserta un producto al que le falte casi todo:

consola de Compass (mongosh)
db.productos.insertOne({ id: 11, nombre: "Sin foto" })
Cómo verificar: MongoDB lo guarda sin quejarse (acknowledged: true). Ahora recarga localhost:5173/productos: la tienda se queda en blanco. Abre la consola del navegador (F12): dice Cannot read properties of undefined (reading 'replace'). La tarjeta intenta usar imagen, que no existe.
Qué aprendiste: MongoDB guarda lo que le des. Las reglas de "campos obligatorios" viven en Mongoose y en la API (por eso POST /api/productos revisa los datos), no en la base. Al insertar directo desde Compass te saltas esa protección: tú eres el responsable de que el documento esté completo.
consola de Compass (mongosh)
db.productos.deleteOne({ id: 11 })
Cómo verificar: con ese comando borras el producto roto (lo verás con detalle en el Paso 4). Recarga la tienda: vuelve a verse con normalidad.
Paso 2 · Read

Leer y filtrar productos

Leer es lo que más vas a hacer. find() es el equivalente de SELECT ... WHERE: sin filtro devuelve todo, y con un objeto filtro devuelve solo lo que cumple. Estos comandos no cambian nada: puedes repetirlos las veces que quieras.

1

Empieza por lo básico. Ejecuta cada línea y mira la respuesta:

consola de Compass (mongosh)
db.productos.find()
db.productos.countDocuments()
db.productos.findOne({ id: 7 })
ComandoQué hace
find()Devuelve todos los documentos de la colección
countDocuments()Devuelve solo cuántos hay, un número
findOne({ id: 7 })Devuelve un documento: el primero que cumple el filtro (aquí, el mouse)
Cómo verificar: find() lista los documentos (si son muchos, la consola ofrece it para ver más), countDocuments() da el total que dejaste en el Paso 1 y findOne muestra el Mouse Logitech completo.
2

Los operadores de comparación filtran por rango. Se escriben dentro de un objeto, con $ delante:

consola de Compass (mongosh)
db.productos.find({ id: { $gt: 6 } })
db.productos.countDocuments({ id: { $gt: 6 } })
OperadorSignificaEjemplo
$gtmayor que{ id: { $gt: 6 } }: los productos con id mayor que 6
$gtemayor o igual{ id: { $gte: 7 } }: el 7 en adelante
$lt / $ltemenor que / menor o igual{ id: { $lt: 3 } }: los ids 1 y 2
$nedistinto de{ id: { $ne: 1 } }: todos menos el id 1
$inestá en la lista{ id: { $in: [1, 3, 5] } }: solo esos tres
Cómo verificar: find({ id: { $gt: 6 } }) devuelve los productos nuevos que creaste (ids 7, 8, 9 y, si hiciste el punto 3 del Paso 1, el 10), y countDocuments da ese mismo número.
3

Para buscar texto se usan las expresiones regulares: una pareja de barras / /. La i final significa "sin distinguir mayúsculas de minúsculas":

consola de Compass (mongosh)
db.productos.find({ nombre: /pro/i })
Cómo verificar: devuelve los productos cuyo nombre contiene "pro": el MacBook Pro M3 y el iPhone 15 Pro (2 documentos).

Cuidado con una trampa. El precio se guarda como texto ("$8.999.000"), no como número. Prueba buscar los productos de más de dos millones:

consola de Compass (mongosh)
db.productos.find({ precio: { $gt: 2000000 } })
Cómo verificar: devuelve 0 documentos, aunque el MacBook cueste casi nueve millones. MongoDB solo compara valores del mismo tipo: un texto no es mayor que un número.
Por eso en S28 el frontend convierte el precio con precioNumero antes de ordenar. En la base, el precio sigue siendo texto. Para buscar por precio con texto se usa una expresión regular, por ejemplo los que empiezan por $1. (más de un millón y menos de dos): db.productos.find({ precio: /^\$1\./ }), que devuelve el Monitor LG y los Audífonos Sony.
4

Tres opciones para elegir qué ver y en qué orden: proyección, orden y límite.

consola de Compass (mongosh)
db.productos.find({}, { nombre: 1, precio: 1, _id: 0 })
db.productos.find().sort({ id: -1 }).limit(3)
ParteQué hace
find({}, { nombre: 1, precio: 1, _id: 0 })El segundo parámetro es la proyección: 1 muestra el campo y 0 lo oculta. Aquí solo ves nombre y precio, sin el _id. El primer {} significa "sin filtro: todos"
.sort({ id: -1 })Ordena por id: 1 de menor a mayor y -1 de mayor a menor
.limit(3)Se queda solo con los primeros 3 resultados
Cómo verificar: la primera línea muestra los productos solo con nombre y precio. La segunda muestra los 3 últimos que creaste, del id más alto hacia abajo.
5

Buscar por _id. Copia el _id del Mouse Logitech de la respuesta de findOne({ id: 7 }) (aparece como ObjectId('…')) y úsalo así, cambiando el texto entre comillas por el tuyo:

consola de Compass (mongosh)
db.productos.find({ _id: ObjectId("tu-id-copiado-aquí") })
Cómo verificar: devuelve exactamente 1 documento. Y ahora prueba lo que hiciste en S29: abre en el navegador localhost:5173/productos/ seguido de ese mismo _id. Se abre la ficha completa de un producto que tú creaste desde la consola.
6

Lo mismo con la barra Filter de Compass. En techstore → productos, escribe en la barra solo el objeto y pulsa Find:

En la barra Filter escribesEquivale a
{ id: { $gt: 6 } }find({ id: { $gt: 6 } })
{ nombre: /pro/i }find({ nombre: /pro/i })
{ id: 7 }findOne({ id: 7 }), pero mostrando la lista
La proyección, el orden y el límite no van dentro del filtro: Compass los tiene en campos aparte. Pulsa Options junto a la barra y verás Project, Sort y Limit: ahí escribes { nombre: 1, precio: 1, _id: 0 }, { id: -1 } y 3.
Paso 3 · Update

Actualizar productos

Actualizar es la operación donde más se cometen errores. Por eso siempre se hace en tres tiempos: buscar → actualizar → buscar. Y se filtra por un identificador único (id), no por el nombre.

1

Cambia el precio del mouse. Ejecuta las tres líneas en orden, una por una:

consola de Compass (mongosh)
db.productos.find({ id: 7 })
db.productos.updateOne({ id: 7 }, { $set: { precio: "$349.000" } })
db.productos.find({ id: 7 })
ParteQué hace
find({ id: 7 })El antes: mira cómo está el documento (precio "$399.000")
updateOne( {filtro}, {cambio} )Tiene dos parámetros: el primero dice a cuál documento y el segundo qué cambiar
{ id: 7 }El filtro: el documento cuyo id vale 7. Un identificador único, para afectar exactamente a uno
{ $set: { precio: "$349.000" } }$set cambia solo ese campo y deja todos los demás intactos. El texto va entre comillas, como siempre en la consola
find({ id: 7 })El después: confirma que el precio ya es "$349.000"
Cómo verificar: la respuesta del updateOne dice matchedCount: 1 (encontró 1 documento) y modifiedCount: 1 (cambió 1). El último find muestra el precio nuevo. Recarga localhost:5173/productos: la tarjeta del mouse ya dice $349.000.
Si ves matchedCount: 1 pero modifiedCount: 0, el documento ya tenía ese valor: no había nada que cambiar. Si ves matchedCount: 0, tu filtro no encontró ningún documento: revisa el id.
2

Cambiar varios campos a la vez es lo mismo: se agregan dentro del mismo $set:

consola de Compass (mongosh)
db.productos.updateOne(
  { id: 7 },
  { $set: { precio: "$329.000", descripcion: "Sensor de 8000 DPI, scroll silencioso, 7 botones y conexión a 3 equipos." } }
)
Cómo verificar: modifiedCount: 1. Al recargar la tienda y abrir la tarjeta del mouse (con Ver ficha completa), se ve el precio y la descripción nuevos.
3

updateMany cambia todos los documentos que cumplan el filtro. Se usa igual que updateOne:

consola de Compass (mongosh)
db.productos.countDocuments({ id: { $gt: 6 } })
db.productos.updateMany({ id: { $gt: 6 } }, { $set: { icono: "📦" } })
Cómo verificar: el updateMany responde matchedCount y modifiedCount iguales al número de productos nuevos que creaste (3 si no hiciste el punto 3 del Paso 1, o 4 si lo hiciste), y que ya contaste con la primera línea.
Antes de un updateMany, cuenta cuántos documentos va a tocar con countDocuments y el mismo filtro. Un filtro demasiado amplio cambia muchos documentos de golpe, y no hay "deshacer".
4

Error que conviene conocer. ¿Qué pasa si te olvidas del $set? Pruébalo:

consola de Compass (mongosh)
db.productos.updateOne({ id: 7 }, { precio: "$1" })
Cómo verificar: MongoDB rechaza el comando con un error: Update document requires atomic operators. Es una protección: te obliga a decir cómo cambiar (con $set) en lugar de reemplazar el documento por accidente. Comprueba con db.productos.find({ id: 7 }) que el mouse sigue intacto.
5

Lo mismo con botones. En techstore → productos, pasa el mouse sobre el documento del mouse y pulsa el lápiz (Edit document). Cambia el valor del campo precio y pulsa Update.

En el editor de campos de Compass, el valor de un texto ya aparece entre comillas: tú cambias solo lo que hay dentro de ellas y no escribes comillas nuevas. Si las escribes, pasan a ser parte del texto y la tarjeta mostrará el precio con comillas. En la consola es distinto: ahí escribes código y todo texto va entre comillas.
Paso 4 · Delete

Borrar productos

Borrar es irreversible: no hay papelera. El ciclo de tres tiempos es aquí más importante que nunca. Y la regla: el filtro nunca puede estar vacío.

1

Borra el producto con id 9 (los audífonos). Buscar → borrar → buscar, en orden:

consola de Compass (mongosh)
db.productos.find({ id: 9 })
db.productos.deleteOne({ id: 9 })
db.productos.find({ id: 9 })
db.productos.countDocuments()
ParteQué hace
find({ id: 9 })El antes: confirma que existe el documento que vas a borrar
deleteOne({ id: 9 })Borra un documento: el primero que cumple el filtro. Por eso el filtro es un identificador único
find({ id: 9 })El después: ya no devuelve nada
countDocuments()Confirma que el total bajó en 1
Cómo verificar: deleteOne responde { acknowledged: true, deletedCount: 1 }. El segundo find no devuelve nada y el conteo bajó en uno. Recarga la tienda: los audífonos ya no están.
2

deleteMany borra todos los que cumplan el filtro. Úsalo para limpiar los productos de prueba que creaste. Primero cuenta, después borra:

consola de Compass (mongosh)
db.productos.countDocuments({ id: { $gt: 6 } })
db.productos.deleteMany({ id: { $gt: 6 } })
db.productos.countDocuments()
Cómo verificar: el primer conteo te dice cuántos va a borrar (los de id mayor que 6 que aún quedan). deleteMany responde con ese mismo deletedCount, y el conteo final es 6: tus productos originales. Recarga la tienda: está como al principio.
Prohibido: db.productos.deleteMany({}) con el filtro vacío borra toda la colección, de golpe y sin preguntar. En local lo arreglas con npm run seed, pero en Atlas no existe ese botón de rescate. Un deleteMany siempre lleva un filtro, y siempre se cuenta antes.
3

Lo mismo con botones. En techstore → productos, pasa el mouse sobre un documento y pulsa el ícono de papelera (Delete document). Compass te pide confirmar con un recuadro rojo: confirma solo si estás seguro de que es el documento correcto.

1

Create desde la aplicación. Abre localhost:5173/contacto y envía dos mensajes con estos datos (uno por vez):

consola de Compass (mongosh)
db.mensajes.find()
Cómo verificar: la consola muestra 2 documentos. Cada uno trae los campos del formulario, un _id, leido: false (los mensajes nuevos nacen sin leer) y una fecha que puso el servidor. Nadie los escribió a mano: los creó POST /api/contacto.
2

Read. Lo que haría quien atiende: ver lo que está pendiente y lo más reciente.

consola de Compass (mongosh)
db.mensajes.find({ leido: false })
db.mensajes.find({ asunto: "soporte" })
db.mensajes.find().sort({ fecha: -1 })
ComandoQué hace
find({ leido: false })Los mensajes sin leer. Un valor false o true se escribe sin comillas
find({ asunto: "soporte" })Solo los del asunto "soporte". El texto va entre comillas

Cómo verificar: la primera línea devuelve los 2 mensajes, la segunda solo el de soporte y la tercera los muestra con el mensaje 2 arriba.
3

Update. La acción típica de una bandeja: marcar un mensaje como leído.

consola de Compass (mongosh)
db.mensajes.updateOne({ email: "prueba1@correo.com" }, { $set: { leido: true } })
db.mensajes.countDocuments({ leido: false })
Cómo verificar: modifiedCount: 1, y countDocuments({ leido: false }) baja de 2 a 1.
Aquí se filtró por el correo para que sea fácil seguirlo. En la vida real un mismo correo puede escribir varias veces, y el filtro tocaría solo el primero. Lo más seguro es filtrar por el _id del mensaje, que es único.
4

Delete. Borra los mensajes ya leídos y después limpia lo que quede de tus pruebas:

consola de Compass (mongosh)
db.mensajes.deleteMany({ leido: true })
db.mensajes.deleteMany({ email: /@correo\.com$/ })
db.mensajes.countDocuments()
ParteQué hace
deleteMany({ leido: true })Borra todos los mensajes marcados como leídos (aquí, 1)
/@correo\.com$/Una expresión regular: correos que terminan en @correo.com. El $ marca el final y la barra invertida \ hace que el punto se lea como punto
Cómo verificar: el primer deleteMany borra 1, el segundo borra el que quedaba y countDocuments() da 0: tu bandeja de pruebas quedó limpia.
Paso 6 · Cierre

Volver a empezar y un reto final

Cuando practicas con datos puedes dejarlos revueltos. Lo bueno de la base local es que siempre puedes volver al punto de partida.

1

Deja el catálogo como al inicio. Con DB_MODO=local, en una terminal dentro de backend/:

terminal — dentro de backend/
npm run seed
ColecciónQué tocaste hoyCómo queda
productosCreaste, leíste, cambiaste y borraste productosnpm run seed la deja con los 6 originales
mensajesLlegaron mensajes del formulario y los administrasteQuedó vacía con el último deleteMany
usuariosNo se toca hoySe llena en S30, cuando registres cuentas desde la tienda (las contraseñas van encriptadas: no se insertan a mano)
ordens y transaccionsNo se tocan hoySe llenan en S31 y S32 con pedidos y pagos de prueba. Guardan referencias (ObjectId) a usuarios y productos
Cómo verificar: db.productos.countDocuments() da 6, db.productos.findOne({ id: 2 }) muestra el iPhone con su precio original y db.mensajes.countDocuments() da 0. La tienda se ve como al principio.
